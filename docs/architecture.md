# 시스템 구성

아무위키는 서버가 초기 문서와 사용자별 데이터를 준비하고, 브라우저가 편집·검색·카드 탐색 같은 상호작용을 이어가는 웹 애플리케이션이다. 외부 영속 계층은 Supabase의 인증, PostgreSQL, 비공개 Storage이며 애플리케이션 서버의 파일시스템은 사용자 데이터 저장소로 사용하지 않는다.

## 구성 요소와 의존 방향

| 영역 | 책임 | 의존 방향 |
|---|---|---|
| 페이지·서버 작업·HTTP 진입점 | 요청 수신, 인증 경계 호출, 입력 검증, 응답과 화면 구성 | UI와 기능 계층을 호출한다 |
| 상호작용 UI | Markdown 편집, 미리보기, 카드 탐색, 검색, 설정, 가져오기 상태 | 서버 작업과 기능 타입·파서를 사용한다 |
| 기능 계층 | 문서, 검색, 최근 기록, 설정, 첨부, 가져오기의 데이터 접근과 결과 변환 | 공통 파서와 Supabase 클라이언트를 사용한다 |
| 공통 기반 | 환경값 검증, 인증 보조, Markdown·Wiki link 처리, 서버·브라우저용 Supabase 클라이언트 | 외부 패키지에만 의존한다 |
| Supabase | 사용자 인증, 사용자별 관계형 데이터, 비공개 파일, 원자적 저장과 권한 정책 | 애플리케이션과 독립적으로 권한을 다시 검사한다 |

페이지는 자신의 HTTP 주소를 다시 호출하지 않고 기능 계층을 직접 사용한다. 브라우저에서 필요한 상호작용만 클라이언트 구성 요소로 두며, 권한이 필요한 최종 읽기와 쓰기는 서버 또는 데이터베이스에서 다시 검증한다.

## 문서 읽기와 연결 탐색

브라우저 요청은 세션 갱신을 거친 뒤 서버 페이지로 들어온다. 서버는 소유자 확인 후 사용자 ID가 포함된 문서 조회를 수행하고, Markdown 안의 Wiki link 대상을 같은 사용자의 제목·별칭과 대조한다. 렌더러는 원시 HTML을 실행하지 않고 해석된 링크에 탐색 정보를 붙인다. 사용자가 링크를 가리키거나 고정하면 짧은 미리보기 주소가 문서 요약과 연결 대상을 반환하고, 전체 문서로 이동하지 않은 채 카드 탐색이 이어진다.

## 문서 저장

브라우저의 입력 중 내용은 해당 기기의 로컬 저장소에 임시 보관된다. 명시적 저장은 서버 작업에서 입력과 소유자를 확인한 뒤 데이터베이스 함수로 전달된다. 데이터베이스는 예상 버전을 대조하고, 문서 변경·리비전 생성·명시적 Wiki link 색인 교체를 한 트랜잭션에서 처리한다. 버전이 다르면 기존 내용을 덮지 않고 충돌 결과를 반환한다.

새 문서에 이미지를 먼저 올리면 숨겨진 임시 문서가 첨부의 소유 대상이 된다. 첫 실제 저장이 성공하면 첨부를 새 문서로 옮기고 임시 문서를 삭제한다. 사용자가 저장하지 않고 떠난 경우는 설정 화면(`/settings/drafts`)의 수동 정리로 처리한다 — 30일 넘게 손대지 않은 임시 문서만 대상이며, 첨부 Storage 객체를 먼저 지운 뒤에만 문서 행을 지운다.

## 가져오기와 내보내기

가져오기는 분석과 확정으로 나뉜다. 분석 요청은 개별 Markdown·텍스트 파일이나 Markdown 폴더·Obsidian vault를 담은 ZIP을 사용자별 비공개 작업 공간에 저장하고 제목·중복·경고·표본을 만든다. ZIP은 경로 이탈·심볼릭 링크·압축 폭탄을 먼저 걸러낸다. 확정 요청은 같은 사용자의 작업인지 다시 확인한 뒤, 묶음 안 모든 문서를 먼저 만들고 상대 경로 첨부를 옮긴 다음, 마지막에 한 번 전체 링크를 다시 색인해 뒤에 만들어질 문서를 가리키는 참조도 연결한다.

내보내기(`/api/export`)는 요청 안에서 바로 ZIP을 만들어 응답한다. 문서마다 frontmatter를 보존한 Markdown 파일, 첨부, id·체크섬·시각을 담은 `manifest.json`, 탐색용 `index.md`를 포함해 외부 도구에서도 읽을 수 있게 한다.

## 확장 경계

현재 로그인 화면은 환경값에 지정한 한 이메일만 허용하지만, 모든 주요 데이터는 사용자 ID를 소유권 기준으로 가진다. 가입을 열 때는 이 애플리케이션 수준 제한과 가입·복구·악용 방지 정책을 교체하되, 사용자별 데이터 경계를 제거하지 않는다. 공개 또는 게시 기능은 기존 개인 데이터 접근을 완화하는 방식이 아니라 별도의 명시적 공개 범위를 추가하는 방식이어야 한다.

배포 대상은 아직 결정되지 않았다. 선택 시 현재 MVP의 운영비와 단순성뿐 아니라 서버리스 실행 시간, 배치 작업, 데이터 백업, 향후 다중 사용자 트래픽을 함께 비교해야 한다.
