# 구현과 검증에서 주의할 점

## 한글 문서 주소가 404가 되는 경우

증상: 한글 제목 문서는 목록에 보이지만 읽기 또는 편집 주소에서 찾을 수 없다. 원인: 브라우저가 한글 slug를 퍼센트 인코딩하고 동적 경로 값도 인코딩된 채 들어올 수 있다. 대응: 문서 조회 전에 안전한 디코더를 사용하고, 잘못된 인코딩은 예외 대신 찾을 수 없음으로 처리한다. 새 동적 문서 경로마다 실제 한글 제목으로 열기와 편집을 확인한다.

## 로그인 직후에만 데이터가 비는 경우

증상: 로그인 링크를 누른 직후 첫 화면에서 문서 조회가 실패하지만 새로고침하면 정상이다. 원인: 세션 쿠키를 설정한 응답과 최종 리다이렉트 응답을 따로 만들면 쿠키가 브라우저에 전달되지 않는다. 대응: 코드 교환에 사용하는 리다이렉트 응답 객체 자체에 쿠키를 기록한다. 콜백 변경 후 로그인 링크부터 첫 문서 목록까지 새 세션으로 확인한다.

## 오래된 개발 서버를 보고 있는 경우

증상: 코드와 검사는 최신인데 브라우저 화면은 이전 동작을 보인다. 원인: 다른 `next start` 또는 개발 서버가 같은 포트를 점유한다. 대응: 브라우저 검증 전에 포트 점유 프로세스와 실행 위치를 확인하고 최신 코드로 시작한 서버인지 검증한다.

## 사용자 파일명이 Storage에서 거부되는 경우

증상: 영문 파일은 가져오지만 한글 파일은 `Invalid key`로 실패한다. 원인: 원본 파일명을 Storage 객체 키로 직접 사용했다. 대응: 화면과 데이터베이스에는 원래 상대 경로를 보존하고, 객체 키에는 UTF-8 상대 경로를 base64url로 바꾼 ASCII 안전값을 사용한다. 업로드와 다운로드가 반드시 같은 변환을 사용하며 한글 파일명으로 왕복을 확인한다.

## 첨부 업로드는 되지만 이미지가 404인 경우

증상: 업로드 응답은 성공하지만 편집 미리보기와 읽기 화면의 이미지가 모두 깨진다. 원인: 응답이 반환한 경로 형태와 실제 GET 진입점이 달랐다. 대응: 업로드 응답의 URL을 브라우저에서 직접 요청하고 이미지의 실제 크기까지 확인한다. 타입 검사만으로는 이 경로 불일치를 찾을 수 없다.

## 새 문서에서 이미지가 고아 데이터로 남는 경우

증상: 이미지만 올린 뒤 저장하지 않고 떠나면 숨겨진 임시 문서와 첨부가 계속 쌓인다. 원인: 첨부에는 문서 ID가 필수라 업로드 시 임시 문서를 만들지만, 저장하지 않은 흐름의 정리 작업이 없다. 대응: 기능 추가 전까지 목록과 검색에서 임시 문서를 계속 제외한다. 정리 작업을 구현할 때는 유예 시간, 소유권, 본문 참조 여부를 확인하고 메타데이터와 실제 파일을 함께 제거하는 검증을 둔다.

## 가져온 문서 제목이 두 번 보이는 경우

증상: 페이지 제목 바로 아래 본문의 첫 줄에도 같은 H1이 반복된다. 원인: 파일명 또는 frontmatter 제목을 문서 제목으로 옮기면서 원문의 동일한 첫 H1도 남겼다. 대응: 정규화한 제목과 동일한 첫 H1만 제거하고 다른 H1은 보존한다. 이미 가져온 문서는 자동으로 소급 수정되지 않는다.

## 배치 안 Wiki link가 일부 연결되지 않는 경우

증상: 같은 가져오기 묶음의 뒤쪽에서 생성될 문서를 앞쪽 문서가 가리키면 링크 색인이 풀리지 않는다. 원인: 현재 확정 과정이 파일마다 생성과 링크 해석을 순차 실행해 전체 제목 카탈로그를 먼저 만들지 않는다. 대응: 사용자가 해당 문서를 다시 저장하면 해결된다. 자동화할 때는 모든 대상 문서를 만든 뒤 묶음 전체를 재색인하는 순서를 검증한다.

## 테마 형태가 서로 달라지는 경우

증상: 테마를 바꿀 때 카드 모서리, 여백 또는 제목 굵기가 함께 변한다. 원인: 공통 형태 토큰을 특정 테마 범위에 넣었다. 대응: 색상만 테마별 파일에 두고 형태 값은 공통 토큰과 전역 스타일에 둔다. 테마 대표색 변경 시 설정 화면의 별도 스와치 맵도 함께 갱신한다.

## 서식 있는 텍스트 붙여넣기가 문서 형식을 깨는 경우

증상: Notion·GPT·Claude에서 복사한 제목, 목록, 표, 코드가 일반 텍스트가 되거나 원시 HTML로 저장된다. 원인: textarea의 기본 붙여넣기는 HTML 의미 구조를 Markdown으로 바꾸지 않으며, 원시 HTML 저장은 현재 Markdown 렌더러의 보안 경계도 우회하려 한다. 대응: `lib/markdown/html-to-markdown.ts`에서 클립보드 HTML을 Markdown으로만 변환한다. 새 형식을 지원할 때는 일반 텍스트·제목·목록·표·인라인 코드·fenced 코드 블록의 단위 테스트를 추가하고, `javascript:` URL과 원시 HTML이 결과에 남지 않는지 확인한다. 이미지 파일은 기존 업로드 흐름이 처리하므로 HTML 이미지 URL을 임의로 파일화하지 않는다.
