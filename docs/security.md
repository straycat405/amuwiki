# 보안과 개인정보 정책

## 보호 대상과 기본값

문서 본문, 리비전, 별칭, 링크 관계, 주석, 검색 기록, 최근 열람 기록, 설정, 가져오기 원본과 첨부파일은 모두 개인 데이터다. 인증되지 않은 방문자와 다른 사용자는 이를 읽거나 만들거나 수정하거나 삭제할 수 없어야 한다. 공개 또는 게시 기능을 추가하더라도 기존 데이터는 비공개로 남고, 사용자가 명시적으로 선택한 대상과 범위만 별도 경로로 공개한다.

현재는 환경값에 등록된 소유자 이메일 하나만 로그인할 수 있다. 로그인 요청은 허용 여부와 무관하게 같은 성공 문구를 반환해 등록 이메일을 드러내지 않고, 허용된 이메일에 대해서만 기존 계정용 로그인 링크를 요청한다. 콜백은 일회성 코드를 세션으로 교환한 뒤 실제 사용자 이메일을 다시 확인한다. 코드가 없거나 교환에 실패하거나 이메일이 다르면 로그인 화면으로 돌아가며, 임의의 외부 주소로 이동시키는 `next` 값은 허용하지 않는다.

로그인 링크와 세션의 실제 만료 시간, 재요청 제한은 Supabase 인증 설정이 결정한다. 현재 저장소는 가입 차단과 허용 콜백 주소만 고정하고 시간값은 고정하지 않았으므로, 만료 시간을 제품에서 임의로 약속해서는 안 된다. 만료되거나 이미 사용한 링크의 코드 교환은 실패로 처리하고 새 링크를 요청하게 한다. 요청 프록시는 매 요청에서 사용자를 확인해 갱신 가능한 세션 쿠키를 반영하며, 갱신할 수 없는 세션은 개인 데이터 접근에 사용할 수 없다. 로그아웃은 Supabase 세션을 폐기하고 로그인 화면으로 이동한다. 강제 로그아웃과 토큰 전체 폐기는 Supabase 운영 도구에서 해당 사용자 세션을 무효화하며, 실제 배포 전에 링크 만료·요청 제한·세션 수명을 명시적으로 결정하고 검증한다.

## 권한 경계

| 주체 | 허용 | 금지 |
|---|---|---|
| 인증되지 않은 방문자 | 로그인 요청과 콜백 접근 | 개인 데이터와 비공개 파일의 모든 읽기·쓰기 |
| 현재 지정 소유자 | 자신의 문서·설정·기록·작업·첨부 관리 | 다른 사용자 ID의 데이터 접근 |
| 향후 일반 사용자 | 자신의 사용자 ID에 속한 공간 관리 | 다른 사용자의 비공개 공간 접근, 소유자 ID 임의 지정 |
| 명시적 공개 방문자 | 공개 정책이 허용한 문서의 게시용 표현 읽기 | 원본 편집, 비공개 메타데이터·리비전·검색 기록·첨부 경로 접근 |
| 서버 운영 작업 | 비밀 저장소의 권한으로 지정 작업과 소유자 범위 처리 | 브라우저에 높은 권한 키 노출, 소유자 범위 없는 일괄 처리 |

애플리케이션의 이메일 검사만 신뢰하지 않는다. 모든 사용자 소유 테이블과 파일 경로는 사용자 ID를 기준으로 데이터베이스와 Storage 권한 정책에서 다시 격리한다. 현재 단일 사용자 제한을 해제하는 작업은 로그인 화면만 바꾸는 것으로 끝내지 않고 가입, 이메일 확인, 계정 복구, 탈퇴, 악용 방지와 사용자별 권한 검사를 함께 설계해야 한다.

## 콘텐츠와 파일

Markdown 원시 HTML은 실행하지 않는다. 외부 링크는 새 창 제어권을 넘기지 않아야 하며, 향후 게시 화면도 편집 화면보다 넓은 스크립트·프레임 권한을 받아서는 안 된다.

첨부파일은 허용된 이미지 형식과 크기를 서버에서 확인하고, 사용자 ID와 문서 ID 아래 내용 해시 기반 경로에 저장한다. 다운로드는 인증된 소유자가 첨부 메타데이터의 소유권을 통과한 뒤에만 비공개 Storage에서 전달한다. 파일 이름이나 요청 경로만으로 다른 사용자의 객체를 읽을 수 있어서는 안 된다. ZIP 가져오기를 추가할 때는 경로 이탈, 심볼릭 링크, 과도한 압축률, 실행 파일과 실제 파일 형식을 검사해야 한다.

## 비밀과 기록

공개 URL과 공개 anon 키만 브라우저에 전달한다. 서버 비밀, 높은 권한 키, 인증 토큰과 로컬 환경파일은 저장소·브라우저 번들·문서·로그에 남기지 않는다. 키를 폐기하거나 교체할 때는 배포 환경과 외부 서비스에서 이전 값을 무효화한 뒤 새 배포가 실제 새 값을 사용하는지 확인해야 한다.

로그에는 문서 본문, 주석 내용, 검색어 전체, 인증 토큰을 기록하지 않는다. 인증 실패, 권한 거부, 데이터 내보내기, 공개 범위 변경, 대량 가져오기·삭제 같은 보안상 중요한 사건은 사용자를 식별할 수 있는 최소 정보와 요청 식별자, 결과를 남기는 방향으로 확장한다. 현재는 통합 감사 로그가 구현되지 않았으므로 존재한다고 가정하지 않는다.

## 삭제와 보존

일반 문서 삭제는 즉시 물리 삭제가 아니라 복원 가능한 휴지통 이동이다. 장기적으로 30일 유예 후 문서·주석·첨부 메타데이터와 실제 파일을 같은 소유자 범위에서 정리하고 삭제 수만 기록한다. 가져오기 원본과 분석 보고서는 작업 완료 후 제한된 기간만 보존한다. 이러한 자동 정리 절차가 구현되기 전에는 데이터가 자동 삭제된다고 사용자에게 약속해서는 안 된다.
