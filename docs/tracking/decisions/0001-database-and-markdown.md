# 데이터베이스 원본과 Markdown 이식성

## 배경

여러 기기에서 검색, 연결 색인, 리비전과 설정을 일관되게 사용하려면 하나의 운영 원본이 필요하다. 동시에 이 제품은 Obsidian에서 얻은 아이디어처럼 사용자의 지식이 특정 서비스에 갇히지 않아야 한다.

## 결정

운영 중 문서와 파생 데이터의 최종 원본은 클라우드 데이터베이스로 둔다. Markdown과 첨부파일은 가져오기, 전체 내보내기와 복구에 사용하며 사용자가 별도 서비스 없이 읽을 수 있는 형태를 보장한다.

## 검토한 대안

- 로컬 Markdown 폴더를 원본으로 두는 방식은 다중 기기 동시 수정, 서버 검색과 권한 경계를 복잡하게 만들어 선택하지 않았다.
- 서비스 전용 형식만 내보내는 방식은 운영은 단순하지만 사용자가 서비스를 떠날 때 지식을 읽고 복구하기 어려워 선택하지 않았다.
- 로컬 폴더와 서버의 지속적인 양방향 동기화는 충돌과 파일 감시 수명주기가 MVP의 중심 경험보다 커져 현재 범위에 넣지 않았다.

## 결과

모든 저장 기능은 데이터베이스 일관성을 먼저 보장해야 한다. 반대로 데이터베이스에만 존재하고 전체 내보내기로 복구할 수 없는 사용자 콘텐츠 형식은 추가할 수 없다.
