# 비공개 기본값과 사용자별 서비스 기반

## 배경

첫 사용자는 제품을 만드는 소유자 한 명이지만, 장기적으로는 여러 사용자가 비용을 지불하고 각자의 지식 공간을 사용하는 서비스를 고려한다. 단일 사용자 전용 스키마를 먼저 만들면 가입을 여는 시점에 데이터 소유권과 권한을 다시 설계해야 한다.

## 결정

현재 애플리케이션 로그인은 지정 이메일 하나로 제한하되, 주요 데이터와 파일은 처음부터 사용자 ID로 소유권을 나눈다. 향후 가입을 열 때도 모든 기존 문서는 비공개로 유지하고, 공유·게시 대상은 사용자가 명시적으로 선택한 별도 공개 범위로 제공한다.

## 검토한 대안

- 전역 단일 소유자 데이터 모델은 초기 구현은 단순하지만 사용자별 서비스 전환 시 모든 테이블과 파일 경로를 이전해야 해 선택하지 않았다.
- 링크를 아는 사람에게 기본 공개하는 방식은 공유가 쉽지만 개인 위키의 기대와 맞지 않고 실수로 민감한 기록을 노출할 수 있어 선택하지 않았다.
- 현재부터 일반 가입을 여는 방식은 계정 복구, 탈퇴, 악용 방지와 운영 지원이 핵심 탐색 경험의 검증을 늦추므로 선택하지 않았다.

## 결과

새 사용자 데이터는 반드시 사용자 ID 경계를 가져야 한다. 가입 개방은 로그인 제한 제거만으로 완료할 수 없으며 계정 수명주기와 운영 안전장치를 함께 구현해야 한다. 공개 기능은 비공개 권한을 느슨하게 만드는 방식으로 추가할 수 없다.
