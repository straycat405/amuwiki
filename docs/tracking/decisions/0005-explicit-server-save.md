# 임시 저장과 명시적 서버 저장 분리

## 배경

작성 중 입력을 잃지 않으면서도 모든 키 입력이 리비전과 링크 색인을 만들면 이력이 과도하게 늘고 동시 수정 의미가 불분명해진다.

## 결정

입력 중 내용은 브라우저 로컬 저장소에 임시 보관한다. 사용자가 저장을 선택했을 때만 예상 서버 버전을 확인하고 문서, 리비전과 링크 색인을 함께 갱신한다.

## 검토한 대안

- 키 입력마다 서버에 저장하는 방식은 기기 간 최신화가 빠르지만 리비전과 재색인 비용이 커지고 충돌이 눈에 보이지 않게 처리될 수 있어 선택하지 않았다.
- 임시 저장을 제공하지 않는 방식은 단순하지만 새로고침과 네트워크 문제에서 작성 중 내용을 잃을 수 있어 선택하지 않았다.

## 결과

로컬 임시는 서버 리비전으로 표시할 수 없다. 서버 버전이 달라지면 자동 덮어쓰지 않아야 하며, 저장 성공은 문서·리비전·링크 색인이 함께 반영된 경우에만 성립한다.
