# 아무위키는 문서 앱으로 보이지만, 핵심 차별점인 연결 탐색은 아직 보이지 않는다

> **상태: 제안 중.** 이 리포트의 권고는 아직 구현되지 않았다. 코드나 다른 문서의 근거로 인용하지 않는다. 실행 지시는 [`ux-ia-improvement-implementation-prompt.md`](ux-ia-improvement-implementation-prompt.md) 참조. 채택되어 구현되면 관련 ADR을 추가하고 이 문서는 `docs/archive/`로 옮긴다.

작성일: 2026-09-16
평가 범위: 로그인된 로컬 환경의 문서 읽기·검색·신규 작성 흐름, 제품 규칙, 관련 UI 구현
목적: 색상·여백·아이콘이 아닌, 처음 방문한 사용자가 서비스를 이해하고 핵심 목적을 달성하는 과정의 구조적 마찰을 찾는다.

## 요약

아무위키는 Markdown을 사용자가 소유하면서, 읽던 문맥을 잃지 않고 관련 개념을 연쇄 탐색하게 하는 개인 지식 도구다. 문서 저장, 검색, 가져오기·내보내기, Wiki link, 최근 문서와 카드 탐색까지 필요한 기반은 이미 폭넓게 구현돼 있다.

그러나 첫 사용자가 화면에서 이해하는 제품은 대체로 “Markdown 문서를 만들고, 최근 문서를 보며, 검색하는 메모 앱”이다. 차별점인 문맥 유지형 탐색은 문서 본문의 평범한 링크 뒤에 숨겨져 있고, 기존 자료를 가져오는 길은 설정 아래에 있으며, 저장 상태의 의미도 충분히 드러나지 않는다.

가장 먼저 해결할 일은 기능 추가가 아니다. 사용자가 첫 2분 안에 다음 네 가지를 이해하도록 제품의 시작 구조를 다시 세우는 일이다.

1. 새 문서를 쓰거나 기존 Markdown을 가져올 수 있다.
2. 문서는 서로 연결할 수 있다.
3. 연결을 열어도 읽던 문맥을 잃지 않는다.
4. 내 자료는 언제든 Markdown으로 내보낼 수 있다.

## 조사 방법과 한계

실제 로그인된 로컬 환경에서 문서 읽기, 최근 문서, 전역 검색, 검색 결과, 새 문서 편집기 화면을 관찰했다. 제품 규칙(`docs/business-rules.md`), 상태 기록(`docs/tracking/status.md`), 페이지·상호작용 구성 요소 구현도 대조했다.

이 평가는 사용성 테스트 참가자의 발화나 행동 로그가 아닌 전문가 검토다. 따라서 “사용자가 반드시 이렇게 행동한다”가 아니라, 현재 인터페이스가 처음 사용자에게 만들 가능성이 높은 해석과 실패를 제시한다. 우선순위 변경 전 5명 내외의 과제 기반 사용성 테스트로 확인해야 한다.

## 현재 사용자가 형성할 정신 모형

| 제품의 실제 의도 | 화면에서 쉽게 형성되는 이해 | 생기는 손실 |
| --- | --- | --- |
| 문서는 연결된 개념의 단위 | 문서는 독립된 노트 파일 | Wiki link의 가치를 늦게 발견한다. |
| 클릭으로 카드 탐색 | 링크는 다른 문서로 이동 | 핵심 탐색 경험을 시도하지 않는다. |
| 명시적 서버 저장과 로컬 임시 저장의 분리 | 자동 저장 여부가 불명확 | 저장 불안, 중복 저장, 이탈 불안을 만든다. |
| Markdown 이식성 | 개발자용 기록 방식 | 비기술 사용자의 시작 장벽이 높아진다. |
| 가져오기·내보내기는 소유권의 핵심 | 설정의 부가 기능 | 기존 자료를 옮길 수 있다는 이유를 놓친다. |

현재 상단에는 검색, 새 문서, 설정이 있고 좌측에는 최근 문서가 있다. 이 배치는 익숙하고 안정적이지만, “연결을 따라 읽는 지식 공간”보다 “문서를 관리하는 앱”이라는 인상을 강하게 만든다.

## 사용자 여정 진단

### 1. 처음 지식 공간을 시작하는 순간

빈 홈은 “아직 문서가 없습니다”와 “새 문서”만 제시한다. 이미 Obsidian, Notion, 로컬 Markdown 폴더를 사용하는 사용자가 가장 먼저 묻는 “기존 자료를 가져올 수 있나?”의 답은 설정 안에 있다.

이 구조는 시작 방법을 잘못 규정한다. 사용자는 아무위키를 새 내용을 처음부터 타이핑해야 하는 곳으로 이해하기 쉽다. 개인 지식 도구에서 초기 콘텐츠 부족은 제품 가치 부족처럼 느껴질 수 있다.

**권고:** 빈 홈에서 `새 문서 작성`과 `Markdown 가져오기`를 동등한 시작 경로로 제시한다. 그 아래에 “문서 안에서 `[[개념]]`을 연결하고, 연결 문서를 현재 자리에서 탐색한다”는 한 문장 설명과 예시 문서를 둔다.

### 2. 생각을 빠르게 기록하는 순간

신규 문서는 제목, 선택 요약, Markdown 본문, 실시간 미리보기, 이미지·파일·코드 입력을 제공한다. 숙련자에게는 충분하지만 첫 사용자는 요약의 목적, Wiki link 문법, 저장 전 내용의 위치, 페이지를 떠나도 되는지를 판단해야 한다.

로컬 임시 저장은 구현돼 있으나, 신규 문서에 초안이 복원된 이유와 현재 저장 상태가 명확히 설명되지 않는다. 사용자가 “서버에 저장됨”과 “이 브라우저에만 임시 저장됨”을 혼동하면 데이터 신뢰가 흔들린다.

**권고:** 편집기 상단에 현재 상태를 명시한다. 예: `이 브라우저에 임시 저장됨` / `서버에 저장됨`. 복원된 초안에는 “이전에 작성하던 임시 내용”이라는 설명과 비파괴적 초기화 선택지를 제공한다. 첫 빈 문서에는 Markdown 문법 설명 대신 “제목을 쓰고, 관련 개념을 `[[ ]]`로 연결해 보세요”라는 행동 중심 안내를 둔다.

### 3. 나중에 필요한 지식을 찾는 순간

전역 검색은 제목·별칭·본문을 대상으로 하고, 최근 검색어와 최근 문서를 함께 제공한다. 실제 관찰에서 `하네스`를 입력한 뒤 약 1초 동안 `검색 결과가 없습니다`가 먼저 보였고, 이후 결과가 도착했다. 이 시간 동안의 빈 결과는 사용자가 검색 실패로 해석할 수 있다.

좌측 사이드바와 검색 창 모두 최근 문서를 보여 준다. 한 화면에서는 회상용 목록, 다른 화면에서는 탐색용 결과가 필요하지만 현재 역할이 겹친다.

**권고:** 요청 중에는 `검색 중…` 또는 결과 스켈레톤을 보여 주고, 응답이 확정된 뒤에만 빈 결과를 보인다. 사이드바는 재방문, 검색 창은 최근 검색과 결과 탐색이라는 역할을 분리한다. 결과에는 제목·별칭·본문 중 어떤 이유로 매치됐는지 표시한다.

### 4. 연결된 개념을 탐색하는 순간

이 여정이 아무위키의 차별점이지만, 가장 발견하기 어렵다. 본문의 Wiki link는 일반적인 파란 링크처럼 보이므로 사용자는 다른 문서로 이동한다고 예상한다. 실제 의도는 클릭 후 현재 문서 위에 고정 카드를 열고, 맥락을 보존한 채 관련 문서를 탐색하는 것이다.

카드가 열린 뒤에도 행동 규칙이 여러 갈래다. 카드 제목은 일반 문서 이동, 외부 아이콘은 새 탭 이동, 닫기와 이동 핸들은 카드 조작이다. 사용자가 “여기서 계속 탐색 중인지”와 “원문으로 돌아갈 수 있는지”를 한눈에 파악하기 어렵다.

제품 규칙은 고정 카드를 최대 세 개로 제한하고 이전 탐색을 경로로 접도록 정한다. 그러나 구현은 최대 열 개를 허용한다. 이 불일치는 단순 제한값 문제가 아니다. 이 기능은 무제한 창 관리가 아니라 제한된 연쇄 탐색으로 문맥을 지키기 위해 존재한다. 열 개의 카드가 겹치면 출발점과 관계를 잃는다.

**권고:** 첫 Wiki link 상호작용에서 “클릭하면 이 자리에서 문서를 엽니다”를 한 번만 안내한다. 카드 수를 세 개로 제한하고, 이전 카드는 `탐색 경로`로 접는다. 카드에는 `현재 문서 → A → B` 같은 경로를 노출한다. 일반 이동, 새 탭 열기, 카드 닫기의 역할을 라벨과 배치로 구분한다.

## 정보구조 진단

현재 설정에는 개인화, AI 키·사용량, 정리 제안, 가져오기, 임시 문서 정리, 내보내기가 한데 들어 있다. 사용자는 설정을 “내 취향을 바꾸는 곳”으로 기대하는데, 실제로는 지식 공간의 입·출구와 수명주기 관리까지 맡는다.

가져오기와 내보내기는 부가 설정이 아니다. 기존 자료를 옮길 수 있고 언제든 떠날 수 있다는 신뢰는 개인 지식 도구의 채택 이유다. 다음 구조가 더 자연스럽다.

```text
문서
├─ 최근 문서
├─ 전체 문서 / 검색
├─ 새 문서
└─ 가져오기

지식 공간 관리
├─ 내보내기
├─ 휴지통
├─ 임시 문서 정리
└─ 정리 제안

개인 설정
├─ 테마·글꼴·읽기 방식
└─ AI 보조 설정
```

푸터의 `휴지통`, `설정` 링크가 모두 홈으로 연결되는 것도 수정해야 한다. 사소해 보여도 전역 탐색의 신뢰를 해친다.

## 우선순위 로드맵

### P0 — 첫 사용 모델 확립

1. 빈 홈에 새 문서와 Markdown 가져오기를 함께 둔다.
2. Wiki link와 카드 탐색이 포함된 예시 문서를 제공한다.
3. 첫 편집에서 행동 중심 안내를 제공한다.
4. 로컬 임시 저장과 서버 저장을 분명히 구분한다.

### P1 — 핵심 차별 경험을 발견 가능하게 만들기

1. Wiki link의 카드 탐색 규칙을 첫 사용 때 안내한다.
2. 카드 수를 세 개로 제한하고 탐색 경로를 유지한다.
3. 카드의 문서 이동·새 탭·닫기 행동을 구분한다.
4. 검색 중 상태를 만들어 잘못된 빈 결과를 제거한다.

### P2 — 지식 공간 관리 정보구조 정리

1. 가져오기를 문서 영역과 빈 홈에서 접근 가능하게 한다.
2. 내보내기·휴지통·임시 문서 정리·정리 제안을 관리 영역으로 묶는다.
3. 설정은 개인화와 AI 보조 설정 중심으로 축소한다.
4. 푸터와 전역 링크의 실제 목적지를 바로잡는다.

## 검증 계획

변경 후에는 다음 과제를 설명 없이 수행하게 하고, 성공률보다 멈춤·되묻기·되돌아가기를 관찰한다.

| 과제 | 성공 기준 |
| --- | --- |
| 기존 Markdown 자료 가져오기 | 2분 안에 가져오기 진입점을 발견한다. |
| 새 생각 기록 | 제목·본문 작성과 저장 상태를 이해한다. |
| 관련 문서 확인 | 현재 문서를 떠나지 않고 카드 탐색을 수행한다. |
| `하네스` 문서 찾기 | 빈 결과를 오해하지 않고 결과를 선택한다. |
| 자료 백업 방법 찾기 | 1분 안에 내보내기 위치를 발견한다. |

관찰해야 할 발화는 “이 버튼을 누르면 뭐가 되죠?”, “저장된 건가요?”, “링크를 누르면 어디로 가죠?”다. 이 질문이 나오는 순간이 다음 개선 대상으로 삼을 구조적 마찰 지점이다.
