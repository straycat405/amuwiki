# 참고 사이트 조사 결과와 인터페이스 개선 제안 (제안, 미채택)

> **상태: 제안 중.** 코드나 다른 문서의 근거로 인용하지 않는다. 채택되면 `docs/tracking/decisions/`에 ADR을 추가하고 이 문서는 `docs/archive/`로 옮긴다.

> 2026-09-16 작성. 나무위키(namu.wiki)와 한국어 위키백과(ko.wikipedia.org)의 실제 페이지를
> 직접 열어 확인한 뒤 정리한 제안이다. 결정된 사항이 아니며, 아래 중 무엇을 구현할지는
> 별도로 정한다. 시각 자료는 [claude.ai 아티팩트](https://claude.ai/artifact/Es5NW5oVZeMwuVAm3W1qeZ)에도
> 있다(외부 링크, 만료·접근 변경 가능성 있음 — 이 파일이 원본 기록).

## 요약

1. 목차 배치 방식이 사이트마다 다르다 — 나무위키는 우측하단 토글로 뜨는 플로팅 패널, 위키백과는
   좌측 고정 레일(읽는 위치에 맞춰 항상 보이고 현재 섹션이 강조됨). 이미 좌측에 "최근 문서"
   사이드바가 있어서 레일 방식은 공간이 부딪힌다.
2. 위키백과의 우측 정보 카드(인포박스)는 이미 저장만 하고 화면에 전혀 안 보이는 frontmatter를
   그대로 활용할 수 있어 비용 대비 가치가 가장 크다.
3. 실시간 검색어·최근 변경 피드·편집 요청/토론 탭 같은 건 여러 사용자가 함께 쓰는 커뮤니티 위키
   전용 기능이라 의도적으로 제안에서 뺐다.
4. 본문 폭 조절은 이미 설정 화면에 있어 추가 작업이 필요 없다.

## 목차: 세 가지 배치 방식

| 방식 | 설명 | 판단 |
|---|---|---|
| 인라인 박스 (지금 구현됨) | 본문 맨 위, 펼침 상태로 시작. 스크롤하면 같이 지나감 | 이미 있음 |
| 플로팅 패널 (나무위키) | 우측하단 아이콘을 누르면 목차가 오버레이로 뜸. 평소엔 화면을 안 차지함 | 선택 가능 |
| 좌측 고정 레일 (위키백과) | 읽는 위치에 맞춰 항상 왼쪽에 보임. 현재 섹션이 강조됨 | 사이드바와 충돌 |

**결정 필요**: 지금 상태(인라인 박스)를 유지할지, 나무위키처럼 우측하단 토글 버튼으로 옮길지
정해야 한다. 좌측 고정 레일은 이미 있는 "최근 문서" 사이드바와 같은 자리를 두고 경쟁하게 되어
추천하지 않는다.

## frontmatter 정보 카드 (제안)

가져오기 시 보존만 하고 화면에 전혀 노출하지 않는 frontmatter를, 위키백과의 인포박스처럼 제목
옆에 key-value 카드로 보여주는 안이다. 새 데이터가 필요 없고, 이미 저장된 값을 꺼내 보여주기만
하면 된다. 예: `문명 6` 문서의 `platforms: PC`, `rating: 5`처럼.

**근거**: 오늘 세션에서 검증한 ZIP 가져오기 테스트 문서가 정확히 이 모양의 frontmatter(`tags`,
`platforms`, `rating` 등)를 이미 저장하고 있었다 — 그냥 안 보여주고 있을 뿐이다. 태그 칩과 정보
카드는 같은 데이터에서 나오므로 하나의 기능으로 묶어 구현할 수 있다.

## 그 밖에 확인한 것

| 패턴 | 출처 | 판단 |
|---|---|---|
| 본문 폭 제한(가독성) | 위키백과·나무위키 공통 | 이미 있음 — 설정 화면 "본문 폭" |
| 맨 위/맨 아래로 이동 버튼 | 나무위키 | 선택 가능 — 긴 문서에서 유용, 구현 비용 낮음 |
| 제목에 세리프, 본문에 산세리프 대비 | 위키백과 | 선택 가능 — 취향 영역, 지금 글꼴 설정과 별개로 판단 필요 |
| 실시간 검색어 / 최근 변경 피드 | 나무위키 | 제외 — 여러 사용자 트래픽 전제, 개인 위키에 의미 없음 |
| 편집 요청·토론·문서 보호 배지 | 나무위키·위키백과 | 제외 — 공동 편집 전제 기능, 소유자 1명 구조와 안 맞음 |
| 문서 상단 "외양" 패널(테마 즉시 전환) | 위키백과 | 제외 — 이미 설정 화면에 동일 기능 있음, 중복 |

## 추천 우선순위

1. **권장** — frontmatter 정보 카드 + 태그 칩: 이미 있는 데이터를 보여주기만 하면 됨. 새
   스키마·마이그레이션 불필요.
2. **검토** — 목차를 우측하단 플로팅 토글로 전환: 지금 방식(상단 인라인)도 충분히 쓸만함 —
   바꾸는 이유가 명확할 때만 진행.
3. **선택** — 맨 위/맨 아래 이동 버튼, 제목 세리프 대비: 둘 다 작고 독립적인 변경이라 아무 때나
   추가해도 리스크가 낮음.

## 정리 — 결정할 것

- **목차 배치** — 지금 상태 유지 vs 나무위키식 플로팅 토글
- **정보 카드 도입 여부** — 도입한다면 카드 위치(제목 옆 vs 우측 레일)
- **태그 칩 클릭 동작** — 같은 태그를 가진 다른 문서로 필터링할지, 지금은 표시만 할지
- **맨 위/아래 버튼, 세리프 제목** — 할지 말지만 정하면 됨 — 작은 변경

조사 방법: 나무위키·한국어 위키백과의 실제 페이지를 직접 열어 확인. 사이트 자체 스크린샷 대신
관찰한 레이아웃 패턴을 도식으로 재구성했다.
