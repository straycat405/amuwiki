# 현재 개발 상태

기준 커밋은 `60160ed`이며 2026-09-16에 현재 작업 트리에서 단위 테스트 134개, 타입 검사, lint, 프로덕션 빌드를 실행했다. 모두 종료 코드 0으로 통과했고 lint에는 Markdown 이미지 렌더링의 `<img>` 사용에 관한 기존 경고 2개가 남아 있다. 이후 커밋 `850941e`에서 가져오기 시 제목·별칭 외 알 수 없는 YAML frontmatter 필드가 저장되지 않던 문제를 고쳤고, 2026-09-16에 로컬 Supabase에 로그인한 브라우저 세션으로 `/api/imports` → `/api/imports/{jobId}/commit`을 실제 호출해 `published`·`tags`·`metadata` 필드와 별칭이 `documents.frontmatter`·`document_aliases`에 그대로 저장되는 왕복을 SQL로 확인했다(테스트 문서는 확인 후 삭제). 같은 날 저장되지 않은 임시 문서·고아 첨부파일 정리 기능(`/settings/drafts`)을 추가했다: 설정 화면의 수동 버튼으로 30일 넘게 손대지 않은 `status='draft'` 문서 중 AI 질문 답변 초안(`frontmatter.ai`)을 제외한 항목만 대상으로 하고, 첨부 Storage 객체를 먼저 삭제한 뒤에만 문서 행을 삭제해(문서 삭제는 첨부 메타데이터 행을 cascade로 정리) Storage 삭제 실패 시 DB 행을 남겨 데이터 유실을 막는다. 로컬 Supabase에 로그인한 브라우저 세션으로 31일 지난 임시 문서와 실제 이미지 첨부를 만들어 목록 표시→삭제→`documents`·`attachments`·`storage.objects` 3곳 모두 SQL로 빈 것을 확인했고, 같은 조건의 AI 답변 초안 문서는 목록에 나타나지 않는 것도 확인했다(테스트 데이터는 확인 후 삭제). 같은 날 ZIP·Obsidian vault 가져오기(`yauzl` 추가, 새 마이그레이션 없이 기존 `import_source_kind`/`import_item_kind` enum 사용)를 붙였다: 중앙 디렉터리 기준 크기로 경로당(문서 5MB·첨부 25MB) 제한과 압축률(100배) 폭탄 검사를 먼저 하고 실제로 열어서 읽을 때도 바이트 수 상한을 다시 확인하며(yauzl `validateEntrySizes`가 선언된 크기와 실제 압축 해제 바이트가 다르면 자체적으로 오류를 낸다), 경로 이탈·심볼릭 링크 항목은 개별적으로, 폭탄 의심 항목은 전체 ZIP을 거부한다. `.obsidian`·숨김 파일·`__MACOSX`·`.DS_Store`는 문서로 만들지 않는다. 커밋은 2단계로 나눠 묶음 안 모든 문서를 먼저 만든 뒤(원문 그대로) 상대 경로 이미지를 첨부 Storage로 옮기고 참조를 새 URL로 바꾸고, 마지막에 `reindexAllDocuments`를 한 번 호출해 묶음 전체를 다시 색인한다 — 이 마지막 단계가 기존에 알려진 "뒤에 생길 문서를 앞서 가리키면 안 연결됨" 버그(engineering-notes.md)를 가져오기 전체에서 고친다. 로컬 Supabase에 로그인한 브라우저 세션으로 Python으로 만든(zip CLI는 UTF-8 파일명 플래그를 안 세워 한글이 깨짐) 실제 vault ZIP을 업로드해 확인했다: `.obsidian`/`.DS_Store` 제외, 뒤에 만들어질 문서를 먼저 만든 문서가 가리켜도(`document_unresolved_links`가 0건으로) 양방향 모두 연결됨, 상대 경로 이미지가 `/api/attachments/{id}`로 바뀌어 실제 200으로 응답, 알 수 없는 frontmatter 보존까지 모두 SQL·화면·네트워크 요청으로 확인했다(테스트 데이터는 확인 후 삭제). 일반 다중 파일 가져오기(ZIP 아님)도 같은 라우트를 공유하도록 리팩터링했으므로 회귀 여부를 같은 방식으로 별도 확인했다. 같은 날 전체 내보내기(`/api/export`)를 붙였다: [0006-synchronous-export](tracking/decisions/0006-synchronous-export.md) 결정에 따라 `export_jobs` 비동기 작업 대신 요청-응답 안에서 바로 ZIP을 만들어 스트리밍한다(배포 방식 미정 + 현재 규모에서는 수 초면 충분). 문서마다 `documents/{slug}.md`로 title·aliases·보존된 frontmatter를 얹고, 라이브 `/api/attachments/{id}` 참조를 `attachments/{slug}/{원본파일명}` 상대 경로로 바꿔 넣으며, `manifest.json`(id·경로·체크섬·생성·수정 시각)과 탐색용 `index.md`를 함께 담는다. 로그인한 브라우저 세션의 실제 쿠키를 재사용한 Node 스크립트로 내보내기 ZIP을 실제로 내려받아 Python `zipfile`로 열어 문서 21개·첨부 3개·manifest 구조·frontmatter·상대 경로 relink(`![...](../attachments/...)`)를 확인했고, 같은 ZIP을 가져오기 분석 단계에 다시 올려 21건 모두 기존 제목과 충돌 판정되는 것으로 왕복 호환성을 확인했다(커밋은 하지 않고 분석 job만 정리). 이 과정에서 이전 단계 정리 스크립트가 content hash로 Storage 객체를 잘못 지워 살아 있는 첨부 2건이 깨졌던 것을 발견해 동일 바이트로 복구했다 — 자세한 내용과 재발 방지는 [findings.md](findings.md) 참조. 문서 개인 주석 기능은 애플리케이션에서 제거했고, 기존 Supabase 주석 테이블·함수·데이터는 보존했다. 본문 부분 일치 검색은 생성 열 `documents.search_text`와 `documents_search_text_trgm_idx` 인덱스를 사용한다. 원본 Markdown은 보존하면서 사용자에게 보이는 본문·링크 표시명·이미지 대체 텍스트만 검색하고, 내부 첨부 API 경로와 식별자는 제외한다. 제목·별칭 우선순위는 유지하면서 본문 결과에는 검색어를 강조한 평문 문맥 미리보기를 반환한다. 명령 팔레트의 최근 검색어는 작은 칩으로 정렬하고 개별·전체 삭제를 유지하며, 열려 있는 동안 50% 검정 백드롭과 전체 화면 클릭 닫기·스크롤 잠금을 적용한다. 로컬 Supabase SQL 검사와 브라우저 검색 화면에서 제목 일치 우선·본문 문맥 미리보기·임시 문서 제외를 확인했다. 로컬 Supabase에서 `ai_settings.sql`·`lint_suggestions.sql`·`document_wiki_links.sql`·`document_crud.sql`·`document_lifecycle.sql`·`annotations.sql`을 실행해 통과했고, `rls.sql`은 픽스처 이메일이 로컬 개발 계정과 겹쳐 실패한다(변경과 무관). 정리 화면은 브라우저에서 요약 저장·새 문서 프리필·정방향 링크 연결·무시·다시 색인을 실제 데이터로 확인했다. AI는 소유자의 OpenAI 키(gpt-5-mini)로 카드 질문→문서 저장, AI 요약 생성→승인을 실제 호출로 확인했다.

## 구현됨·이번에는 통합 검사를 다시 실행하지 않음

- 소유자 이메일 한 명을 허용하는 매직 링크 로그인과 안전한 콜백 경로
- 사용자 ID 기반 스키마와 주요 테이블·Storage의 행 단위 권한 정책
- 문서 생성·수정, 명시적 저장, 리비전, 버전 충돌, 휴지통 이동·복원
- 제목·별칭, 명시적 Wiki link, 백링크와 한글 문서 주소
- Markdown 렌더링, 원시 HTML 차단, 외부 링크 보호, 줄바꿈 선택
- 호버 미리보기, 클릭 고정 카드, 카드 안 연결 탐색, 이미지 확대 보기
- 제목·별칭·사용자에게 보이는 본문 검색, 평문 문맥 미리보기, 최근 검색어, 실제 열람 기반 최근 문서
- 이미지 업로드·붙여넣기, 비공개 다운로드, 내용 해시 기반 중복 제거
- 저장되지 않은 임시 문서·고아 첨부파일 정리(`/settings/drafts`): 30일 유예, AI 답변 초안 제외, Storage와 DB 일관 삭제(수동 실행, 실제 흐름 검증 완료)
- `.md`, `.markdown`, `.txt` 다중 파일 분석·미리보기·가져오기와 충돌 시 건너뛰기·이름 바꾸기, 제목·별칭 외 알 수 없는 frontmatter 필드 보존(왕복 검증 완료)
- ZIP·Obsidian vault 가져오기: 경로 이탈·심볼릭 링크·압축 폭탄 방어, `.obsidian`/숨김 파일 제외, 묶음 전체 카탈로그 확정 후 링크 재색인, 상대 경로 이미지 첨부 이전과 링크 치환(실제 브라우저 흐름 검증 완료)
- 전체 내보내기(`/api/export`, 동기 방식): Markdown·frontmatter·별칭·첨부·manifest.json·index.md를 담은 ZIP, 실제 다운로드와 가져오기 왕복 호환성 검증 완료
- 테마·명암·글꼴·크기·본문 폭·미리보기 설정과 새로고침 후 유지
- 정리 제안(설계 13절 A0): 미해석 링크 저장, 고아·깨진 링크·정방향 링크·빈 요약 제안, 승인·무시, 첫 문단 요약 파생, 전체 다시 색인
- AI BYOK(설계 13절 A1): 공급자 추상화(Anthropic·OpenAI), 키 암호화 저장·검증·삭제·월 한도, 사용량 화면, 고정 카드 안 질문(스트리밍)과 답변의 초안 문서 저장, 파생 불가 문서의 AI 요약 제안

이 목록에는 단위 테스트가 포함된 기능도 있지만, 로컬 Supabase SQL 검사와 로그인부터 저장·가져오기까지의 브라우저 전 과정은 과거 기록만 있고 이번 작업에서는 다시 실행하지 않았다.

## 남은 작업 순서

1. AI 후속(선택): 암호화 비밀 로테이션 스크립트, A2(깨진 링크 초안·모순 검사·편집기 diff 제안), 공급자 추가(Gemini).

내보내기 왕복은 같은(비어 있지 않은) 로컬 환경에 다시 올려 제목 충돌로 판정되는 것까지만 확인했고, 완전히 빈 환경에 복원하는 것은 아직 확인하지 않았다.

가져오기 스테이징 버킷(`data-jobs`)과 ZIP 원본·분석 보고서를 7일 뒤 지우는 주기 작업은 아직 없다(설계 12절 명시, 소유자 정리 화면과 같은 종류의 자동 삭제 인프라 확정 필요 — [findings.md](findings.md) 참조).

## 후속 범위

- 모바일에서 카드 탐색을 동일하게 사용할 수 있는 하단 시트·키보드·스크린리더 경험
- 가져오기 부분 실패 재시도, 정기 백업과 복원 리허설, 감사 기록과 운영 알림
- 개인 사용 경험 검증 후 일반 가입·계정 복구·탈퇴·악용 방지를 포함한 다중 사용자 서비스 전환
- 사용자가 선택한 문서를 명시적으로 공유하거나 게시하는 기능
- 서비스 운영비, 배치 작업, 백업과 사용자 증가를 함께 고려한 배포 대상 결정

협업 편집, 추천 피드, 그래프 화면, 플러그인 생태계는 핵심 기록·탐색·이식 경험이 검증된 뒤 평가한다. AI는 설계 13절의 제안 방식(BYOK, 원문 자동 수정 없음)으로만 도입하며 A2 이후는 Personal MVP 이후에 판단한다.
