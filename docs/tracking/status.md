# 현재 개발 상태

기준 커밋은 `60160ed`이며 2026-09-16에 현재 작업 트리에서 단위 테스트 134개, 타입 검사, lint, 프로덕션 빌드를 실행했다. 모두 종료 코드 0으로 통과했고 lint에는 Markdown 이미지 렌더링의 `<img>` 사용에 관한 기존 경고 2개가 남아 있다. 이후 커밋 `850941e`에서 가져오기 시 제목·별칭 외 알 수 없는 YAML frontmatter 필드가 저장되지 않던 문제를 고쳤고, 2026-09-16에 로컬 Supabase에 로그인한 브라우저 세션으로 `/api/imports` → `/api/imports/{jobId}/commit`을 실제 호출해 `published`·`tags`·`metadata` 필드와 별칭이 `documents.frontmatter`·`document_aliases`에 그대로 저장되는 왕복을 SQL로 확인했다(테스트 문서는 확인 후 삭제). 같은 날 저장되지 않은 임시 문서·고아 첨부파일 정리 기능(`/settings/drafts`)을 추가했다: 설정 화면의 수동 버튼으로 30일 넘게 손대지 않은 `status='draft'` 문서 중 AI 질문 답변 초안(`frontmatter.ai`)을 제외한 항목만 대상으로 하고, 첨부 Storage 객체를 먼저 삭제한 뒤에만 문서 행을 삭제해(문서 삭제는 첨부 메타데이터 행을 cascade로 정리) Storage 삭제 실패 시 DB 행을 남겨 데이터 유실을 막는다. 로컬 Supabase에 로그인한 브라우저 세션으로 31일 지난 임시 문서와 실제 이미지 첨부를 만들어 목록 표시→삭제→`documents`·`attachments`·`storage.objects` 3곳 모두 SQL로 빈 것을 확인했고, 같은 조건의 AI 답변 초안 문서는 목록에 나타나지 않는 것도 확인했다(테스트 데이터는 확인 후 삭제). 같은 날 ZIP·Obsidian vault 가져오기(`yauzl` 추가, 새 마이그레이션 없이 기존 `import_source_kind`/`import_item_kind` enum 사용)를 붙였다: 중앙 디렉터리 기준 크기로 경로당(문서 5MB·첨부 25MB) 제한과 압축률(100배) 폭탄 검사를 먼저 하고 실제로 열어서 읽을 때도 바이트 수 상한을 다시 확인하며(yauzl `validateEntrySizes`가 선언된 크기와 실제 압축 해제 바이트가 다르면 자체적으로 오류를 낸다), 경로 이탈·심볼릭 링크 항목은 개별적으로, 폭탄 의심 항목은 전체 ZIP을 거부한다. `.obsidian`·숨김 파일·`__MACOSX`·`.DS_Store`는 문서로 만들지 않는다. 커밋은 2단계로 나눠 묶음 안 모든 문서를 먼저 만든 뒤(원문 그대로) 상대 경로 이미지를 첨부 Storage로 옮기고 참조를 새 URL로 바꾸고, 마지막에 `reindexAllDocuments`를 한 번 호출해 묶음 전체를 다시 색인한다 — 이 마지막 단계가 기존에 알려진 "뒤에 생길 문서를 앞서 가리키면 안 연결됨" 버그(engineering-notes.md)를 가져오기 전체에서 고친다. 로컬 Supabase에 로그인한 브라우저 세션으로 Python으로 만든(zip CLI는 UTF-8 파일명 플래그를 안 세워 한글이 깨짐) 실제 vault ZIP을 업로드해 확인했다: `.obsidian`/`.DS_Store` 제외, 뒤에 만들어질 문서를 먼저 만든 문서가 가리켜도(`document_unresolved_links`가 0건으로) 양방향 모두 연결됨, 상대 경로 이미지가 `/api/attachments/{id}`로 바뀌어 실제 200으로 응답, 알 수 없는 frontmatter 보존까지 모두 SQL·화면·네트워크 요청으로 확인했다(테스트 데이터는 확인 후 삭제). 일반 다중 파일 가져오기(ZIP 아님)도 같은 라우트를 공유하도록 리팩터링했으므로 회귀 여부를 같은 방식으로 별도 확인했다. 같은 날 전체 내보내기(`/api/export`)를 붙였다: [0006-synchronous-export](tracking/decisions/0006-synchronous-export.md) 결정에 따라 `export_jobs` 비동기 작업 대신 요청-응답 안에서 바로 ZIP을 만들어 스트리밍한다(배포 방식 미정 + 현재 규모에서는 수 초면 충분). 문서마다 `documents/{slug}.md`로 title·aliases·보존된 frontmatter를 얹고, 라이브 `/api/attachments/{id}` 참조를 `attachments/{slug}/{원본파일명}` 상대 경로로 바꿔 넣으며, `manifest.json`(id·경로·체크섬·생성·수정 시각)과 탐색용 `index.md`를 함께 담는다. 로그인한 브라우저 세션의 실제 쿠키를 재사용한 Node 스크립트로 내보내기 ZIP을 실제로 내려받아 Python `zipfile`로 열어 문서 21개·첨부 3개·manifest 구조·frontmatter·상대 경로 relink(`![...](../attachments/...)`)를 확인했고, 같은 ZIP을 가져오기 분석 단계에 다시 올려 21건 모두 기존 제목과 충돌 판정되는 것으로 왕복 호환성을 확인했다(커밋은 하지 않고 분석 job만 정리). 이 과정에서 이전 단계 정리 스크립트가 content hash로 Storage 객체를 잘못 지워 살아 있는 첨부 2건이 깨졌던 것을 발견해 동일 바이트로 복구했다 — 자세한 내용과 재발 방지는 [findings.md](findings.md) 참조. 같은 날 README를 오픈소스 공개를 가정하고 다시 썼고(실제 배포 사례 여러 개를 읽고 구조를 참고했다), 새로 받은 로고(화이트 단색 심볼·워드마크, `public/brand/`에 원본 보관)를 파비콘·README 헤더·앱 헤더 브랜드마크 세 곳에 적용했다 — 헤더 마크는 `mask-image` + `background-color: var(--color-accent)`로 입혀 라이트/다크와 3개 색상 테마 전부에서 별도 배리언트 없이 자동으로 맞는 것을 브라우저로 확인했다. 이어서 사이드바 "최근 문서"의 긴 제목이 `text-overflow: ellipsis`가 있어도 안 잘리던 버그를 고쳤다(원인: `display: grid`인데 `grid-template-columns`가 없어 열이 내용에 맞춰 늘어남), 오늘/어제/지난 7일/지난 30일/이전으로 날짜 그룹을 나눴고, 목록에 스크롤 처리가 없어 넘치면 잘리던 것을 고치면서 커서 기반 무한 스크롤(`listRecentViewsPage`, `IntersectionObserver`)을 붙였다 — 페이지 크기를 임시로 줄여 실제로 여러 페이지를 이어붙이는 과정에서 관찰자 재생성으로 인한 중복 fetch와 sentinel이 화면 밖으로 안 밀려나 로딩이 멈추는 문제를 둘 다 발견해 고쳤다(최종 DOM에 중복 0건 확인). 마지막으로 문서 제목 글자 크기를 최대 4rem에서 2.35rem으로 줄이고, `##`~`####` 헤딩으로 목차를 자동 생성해 클릭하면 해당 위치로 스크롤 이동하는 기능을 추가했다(부수 효과로 기존 `[[문서#제목]]` 링크가 가리키던 존재하지 않는 앵커도 같이 고쳐졌다). 나무위키·위키백과 실제 페이지를 조사해 정리한 인터페이스 개선 제안은 [wiki-interface-proposal.md](wiki-interface-proposal.md)에 남겨뒀고 아직 채택되지 않았다. 문서 개인 주석 기능은 애플리케이션에서 제거했고, 기존 Supabase 주석 테이블·함수·데이터는 보존했다. 본문 부분 일치 검색은 생성 열 `documents.search_text`와 `documents_search_text_trgm_idx` 인덱스를 사용한다. 원본 Markdown은 보존하면서 사용자에게 보이는 본문·링크 표시명·이미지 대체 텍스트만 검색하고, 내부 첨부 API 경로와 식별자는 제외한다. 제목·별칭 우선순위는 유지하면서 본문 결과에는 검색어를 강조한 평문 문맥 미리보기를 반환한다. 명령 팔레트의 최근 검색어는 작은 칩으로 정렬하고 개별·전체 삭제를 유지하며, 열려 있는 동안 50% 검정 백드롭과 전체 화면 클릭 닫기·스크롤 잠금을 적용한다. 로컬 Supabase SQL 검사와 브라우저 검색 화면에서 제목 일치 우선·본문 문맥 미리보기·임시 문서 제외를 확인했다. 로컬 Supabase에서 `ai_settings.sql`·`lint_suggestions.sql`·`document_wiki_links.sql`·`document_crud.sql`·`document_lifecycle.sql`·`annotations.sql`을 실행해 통과했고, `rls.sql`은 픽스처 이메일이 로컬 개발 계정과 겹쳐 실패한다(변경과 무관). 정리 화면은 브라우저에서 요약 저장·새 문서 프리필·정방향 링크 연결·무시·다시 색인을 실제 데이터로 확인했다. AI는 소유자의 OpenAI 키(gpt-5-mini)로 카드 질문→문서 저장, AI 요약 생성→승인을 실제 호출로 확인했다.

2026-09-17에 커밋 `d90731a`로 두 가지를 바꿨다. 첫째, 로그인을 매직 링크에서 이메일/비밀번호(`supabase.auth.signInWithPassword`)로 교체했다 — 별도 사용자 테이블 없이 기존 `auth.users`와 `OWNER_EMAIL` 게이트를 그대로 쓰며, `/auth/callback` 라우트는 남겨둬서 나중에 소셜 로그인을 추가할 때 같은 콜백을 재사용할 수 있게 했다. 둘째, ZIP 가져오기 분석·커밋 라우트가 항목마다 Storage 요청을 순차 `await`로 처리하던 것을 16개씩 병렬 배치로 바꾸고 `reindexAllDocuments`도 같은 방식으로 병렬화했다. 이 과정에서 실제 프로덕션(Vercel Hobby + Supabase 서울 리전)에 239개 문서짜리 ZIP을 올려보다가 발견한 문제들이다: 서버리스 함수 기본 리전이 Supabase와 달라 요청마다 지연이 누적됐고(`preferredRegion = "icn1"`로 고침), 기본 실행시간 10초를 넘어 항상 실패했으며(각 라우트에 `maxDuration = 60` 추가), 60초로도 부족해 커밋이 여러 번 끊겼는데 재시도할 때마다 이미 끝난 항목까지 처음부터 다시 다운로드·재시도하고 있어 갈수록 느려졌다(커밋 라우트가 `import_items.status`가 이미 `imported`/`skipped`인 항목은 건너뛰도록 고쳤다). 이 조합으로 같은 커밋 요청을 4번 다시 보내 239개 전부(로컬에서 먼저 검증한 것과 동일한 배치)를 실제 프로덕션 Supabase에 채우는 것까지 확인했다 — 다만 이건 60초 제한을 재시도로 우회하는 것일 뿐 근본 해결은 아니며, 진짜 해결(비동기 작업 큐)은 하지 않았다. 같은 날 Vercel 프로젝트(`straycat405/amuwiki`)를 만들고 GitHub 리포(`straycat405/amuwiki`)를 Git 연동으로 연결해 `main` push마다 자동 배포되게 했다. 배포 대상 결정(전에는 미정)과 이 모든 변경은 [operations.md](../operations.md#배포)에 반영했다.

- 전체 내보내기(`/api/export`, 동기 방식): Markdown·frontmatter·별칭·첨부·manifest.json·index.md를 담은 ZIP, 실제 다운로드와 가져오기 왕복 호환성 검증 완료
- 로고 적용(파비콘·README·앱 헤더), 사이드바 최근 문서 제목 말줄임·날짜 그룹·커서 기반 무한 스크롤, 문서 본문 목차 자동 생성과 클릭 이동(전부 실제 브라우저 검증 완료)
- 테마·명암·글꼴·크기·본문 폭·미리보기 설정과 새로고침 후 유지
- 정리 제안(설계 13절 A0): 미해석 링크 저장, 고아·깨진 링크·정방향 링크·빈 요약 제안, 승인·무시, 첫 문단 요약 파생, 전체 다시 색인
- AI BYOK(설계 13절 A1): 공급자 추상화(Anthropic·OpenAI), 키 암호화 저장·검증·삭제·월 한도, 사용량 화면, 고정 카드 안 질문(스트리밍)과 답변의 초안 문서 저장, 파생 불가 문서의 AI 요약 제안

이 목록에는 단위 테스트가 포함된 기능도 있지만, 로컬 Supabase SQL 검사와 로그인부터 저장·가져오기까지의 브라우저 전 과정은 과거 기록만 있고 이번 작업에서는 다시 실행하지 않았다.

## 남은 작업 순서

1. AI 후속(선택): 암호화 비밀 로테이션 스크립트, A2(깨진 링크 초안·모순 검사·편집기 diff 제안), 공급자 추가(Gemini).

내보내기 왕복은 같은(비어 있지 않은) 로컬 환경에 다시 올려 제목 충돌로 판정되는 것까지만 확인했고, 완전히 빈 환경에 복원하는 것은 아직 확인하지 않았다.

가져오기 스테이징 버킷(`data-jobs`)과 ZIP 원본·분석 보고서를 7일 뒤 지우는 주기 작업은 아직 없다(설계 12절 명시, 소유자 정리 화면과 같은 종류의 자동 삭제 인프라 확정 필요 — [findings.md](findings.md) 참조).

목차 배치 방식 변경(우측하단 플로팅 토글 등)과 frontmatter 정보 카드·태그 칩은 [wiki-interface-proposal.md](wiki-interface-proposal.md)에 제안만 남겨뒀고 결정되지 않았다.

## 후속 범위

- 모바일에서 카드 탐색을 동일하게 사용할 수 있는 하단 시트·키보드·스크린리더 경험
- 가져오기 대량 배치의 진짜 비동기 처리(현재는 60초 함수 제한을 같은 요청 재시도로 우회하는 임시방편, 위 참조), 정기 백업과 복원 리허설, 감사 기록과 운영 알림
- 개인 사용 경험 검증 후 일반 가입·계정 복구·탈퇴·악용 방지를 포함한 다중 사용자 서비스 전환
- 사용자가 선택한 문서를 명시적으로 공유하거나 게시하는 기능
- 서비스 운영비, 배치 작업, 백업과 사용자 증가를 함께 고려한 배포 대상 결정 (GitHub Actions 중심 CI/CD 제안은 [ci-cd-deployment-proposal.md](ci-cd-deployment-proposal.md) 참조, 아직 미채택)

협업 편집, 추천 피드, 그래프 화면, 플러그인 생태계는 핵심 기록·탐색·이식 경험이 검증된 뒤 평가한다. AI는 설계 13절의 제안 방식(BYOK, 원문 자동 수정 없음)으로만 도입하며 A2 이후는 Personal MVP 이후에 판단한다.
