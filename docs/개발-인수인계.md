# 아무위키 개발 인수인계

최종 갱신: 2026-09-15 (정리(lint) 제안 화면·미해석 링크 저장·요약 파생 반영)

## 작업 원칙

- 사용자와의 모든 대화는 한국어로 한다.
- 기능 단위마다 `npm run test`, `npm run typecheck`, `npm run lint`, `npm run build`를 실행한다.
- DB 변경은 마이그레이션으로만 추가한다. 기존 사용자의 로컬 문서를 지우는 `supabase db reset`은 명시적인 필요·승인 없이는 실행하지 않는다.
- 기능 또는 버그 수정이 끝나면 반드시 커밋하고 `origin/main`에 푸시한다.
- 사용자 데이터, 계정, 외부 서비스 설정처럼 되돌리기 어렵거나 제품 정책을 바꾸는 작업은 구현 전에 확인한다.
- 작업을 시작하기 전에 범위·설계가 불확실하거나 확인이 필요한 부분이 있으면 반드시 먼저 물어보고 답을 받은 뒤 진행한다. 애매한 채로 진행해서 다시 작업하는 일이 없도록 한다.

## 구현 완료 항목

### 기반·인증·문서

- 소유자 1인 이메일 매직 링크 로그인. DB와 RLS는 다중 사용자 격리 구조다.
- 문서 생성·조회·수정, 명시적 서버 저장, localStorage 임시 자동 저장, 리비전·낙관적 버전 충돌 처리.
- 휴지통 소프트 삭제·복원.
- Markdown 렌더링(GFM, raw HTML 비활성화)과 Wiki link 문법:
  - `[[문서 제목]]`
  - `[[문서 제목|표시명]]`
  - `[[문서#제목]]`
- 제목 변경 시 이전 제목을 별칭으로 보존하고, 제목·별칭 충돌은 저장을 거부한다.
- 저장 시 명시 링크를 `document_links`에 색인하고, 읽기 화면에 역링크와 언급 횟수를 표시한다.

### 탐색 경험

- Wiki link 호버 미리보기(기본 지연 450ms, 설정 화면에서 250~800ms 및 켬/끔 조절 가능).
- 링크 클릭 시 고정 카드, 카드 내 중첩 링크, 카드 드래그 이동, 최대 3개 고정 카드.
- 미리보기 API는 인증된 소유자만 사용한다: `GET /api/documents/preview?slug=...`.
- **사이드바 접기/펼치기:** 헤더 좌측 토글 버튼(`components/shell/sidebar-toggle-button.tsx`)으로 사이드바를 완전히 숨기고 본문 폭을 넓힐 수 있다. 상태는 `localStorage`(`amuwiki:sidebar-collapsed`)에 저장돼 새로고침 후에도 유지된다. 드래그로 폭을 조절하는 기능은 범위에서 제외했다(사용자 확인 후 결정). 모바일 폭(≤760px)에서는 사이드바가 이미 항상 숨겨져 있어 토글 버튼 자체를 숨긴다.
- **이미지 확대 보기(라이트박스):** `MarkdownRenderer`가 모든 이미지에 클릭 핸들러를 붙여 전체 화면 오버레이로 원본 크기를 보여준다(배경 클릭·닫기 버튼·Esc로 닫힘). 편집기 미리보기·읽기 화면·호버 카드 등 `MarkdownRenderer`를 쓰는 모든 곳에 자동으로 적용된다.

### 줄바꿈

- 기본 렌더 정책은 `hard`: 편집기의 Enter 한 번이 읽기·미리보기 화면에서 `<br>`로 표시된다.
- 인라인 코드·코드 블록은 영향을 받지 않는다.
- `user_preferences.line_break_mode`(`hard | soft`)는 설정 화면에서 변경할 수 있고, `MarkdownRenderer`가 즉시 반영한다.

### 설정 화면

- 경로: `/settings`. `user_preferences`의 7개 컬럼(`theme_key`, `color_mode`, `font_preset`, `font_scale`, `content_width`, `tooltip_enabled`, `tooltip_delay_ms`, `line_break_mode`)을 전부 노출한다. `tooltip_lock_mode`는 DB 체크 제약상 `click` 한 값만 허용되어 설정 항목에서 제외했다.
- **DB가 최종 원본이다.** 컨트롤을 조작하면 `PreferencesProvider`가 화면에 즉시 반영(낙관적 업데이트)한 뒤 `updatePreferencesAction`으로 저장하고, 실패하면 이전 값으로 되돌리며 오류 메시지를 보여준다.
- `localStorage`(`amuwiki:appearance`)는 테마·명암·글꼴·글자크기·본문폭만 캐시해 `app/layout.tsx`의 `beforeInteractive` 스크립트가 첫 페인트 전에 적용한다. **쿠키 캐시는 아직 구현하지 않았다** — 제품 설계 문서(279행)는 로컬 저장소와 쿠키 모두를 언급하지만 현재는 로컬 저장소만 있다.
- 글자 크기(`--font-scale`)와 본문 폭(`--content-width`) 값은 `styles/tokens.css`의 `data-scale`/`data-width` 속성으로 제어한다.
- 호버 미리보기 지연·활성화는 `components/document/wiki-link-explorer.tsx`가 `usePreferences()`로 읽는다. `tooltip_enabled`가 꺼지면 호버 시작 자체를 막고, 클릭으로 카드를 고정하는 동작에는 영향을 주지 않는다.
- **4번째 테마 `midnight` 추가.** 사용자가 다른 블로그(kdy1.dev)의 다크 스타일을 마음에 들어해서, 브라우저로 그 페이지를 직접 열어 `getComputedStyle`로 실측한 값(배경 `oklch(0.21 0.009 255)`, 카드 `oklch(0.24 0.0095 255)`, 테두리 `oklch(0.32 0.011 255)`, 강조색 `oklch(0.65 0.2 264)`, 카드 radius 14px·패딩 32px)을 그대로 이식했다. 폰트는 원본이 유료 상업 폰트(`suisseIntl`)라 그대로 못 쓰고 기존 Pretendard를 유지했다. 라이트 모드 값은 참고 사이트에 없어서 같은 색 계열로 새로 만들었다(추측치, 참고 사이트와 대조 검증 안 됨 — 다크 모드만 실측 대조함).
  - DB `user_preferences.theme_key` 체크 제약에 `'midnight'` 추가(`supabase/migrations/202609140009_midnight_theme.sql`) — 제약 이름은 Postgres가 자동 생성한 `user_preferences_theme_key_check`라서 `drop constraint` 후 재생성하는 방식으로 작성했다.
- **radius(14px)·간격(`--space-6` 32px)·제목 타이포(`font-weight:800`, `letter-spacing:-0.03em`)는 4개 테마 전체에 공통 적용한다 — `midnight`만의 스코프가 아니다.** 처음엔 `:root[data-theme="midnight"]`로 스코프를 좁혀 넣었는데, 사용자가 테마 전환 시 카드 모서리·여백이 테마마다 달라 보인다고 지적해서 `styles/tokens.css`의 기본 `:root` 값 자체를 이 사양으로 올리고 테마별 오버라이드는 제거했다. 색상만 테마마다 다르고, 형태(둥근 정도·여백·헤딩 굵기)는 전 테마 공통이라는 뜻 — 새 테마를 추가할 때도 이 형태 값은 건드리지 않는다.
- **테마 선택 UI를 텍스트 라벨 없는 색상 스와치(원형 버튼)로 변경.** "구글 프로필처럼 이름 없이 색만 보고 고르게 해달라"는 요청 — `색상 테마`만 스와치로 바꿨고, 다른 설정 항목(명암·글꼴 등)은 그대로 텍스트 라벨 라디오 유지. 스와치 색상은 각 테마의 대표 accent 색을 하드코딩한 값(`components/settings/settings-form.tsx`의 `themeSwatchColors`)이라 `themes.css`를 바꾸면 이 맵도 같이 업데이트해야 한다(자동 동기화 안 됨).

### 검색·최근 기록

- **검색 UI 둘 다 구현:** 헤더의 `⌘K` 커맨드 팔레트(`components/search/command-palette.tsx`)와 별도 `/search` 페이지. 팔레트는 결과 미리보기·빠른 탐색용, 페이지는 JS 없이도 동작하는 GET 폼 기반이라 URL 공유가 가능하다.
- **검색 범위는 제목·별칭만.** 본문 검색은 아직 없다(다음 우선순위 참고).
- **랭킹:** 제목 완전 일치 > 별칭 완전 일치 > 제목/별칭 접두어 일치 > trigram 유사도, 마지막 동점 처리는 최근 열람 시각. 전부 `search_documents` SQL 함수(`supabase/migrations/202609140007_search_and_history.sql`)가 계산하며, `security invoker` + `auth.uid()`로 RLS를 그대로 적용받는다. **이 함수만 `set search_path = public`으로 고정한다** — `similarity()`/`%` 연산자가 `pg_trgm`과 함께 `public` 스키마에 있기 때문에 다른 함수처럼 `search_path = ''`로 비우면 안 된다.
- **디바운스 150ms, 요청 취소:** 팔레트는 `requestId` 카운터로 낡은 응답을 무시한다.
- **최근 검색어(`recent_searches`)**: 검색을 "확정"한 시점(팔레트에서 Enter/클릭, `/search` 페이지 접근)에만 기록한다. 키 입력마다 기록하지 않는다. 개별 삭제·전체 삭제 모두 구현(`전체 삭제`는 `window.confirm` 확인 후 진행).
- **최근 문서(`recent_views`)**: 사이드바 "최근 문서"가 이제 실제 열람 기록이다(이전에는 `updated_at` 기준이었음 — 라벨과 동작이 불일치했던 문제를 이번에 해결). 문서 읽기 페이지(`app/(wiki)/documents/[slug]/page.tsx`)가 매 조회마다 `record_document_view` RPC를 호출해 `view_count` 증가·`last_viewed_at` 갱신·`hidden_at` 초기화를 원자적으로 처리한다.
  - **주의:** 지금 보고 있는 문서 자체를 사이드바에서 "제거"해도 그 문서를 계속 보고 있으면(새로고침·재방문) 다시 나타난다 — 페이지 렌더 자체가 열람 기록을 남기기 때문이다. 이는 의도된 동작이다(제거는 "다시 열기 전까지 숨김"이라는 `hidden_at` 설계와 일치).
- 홈 화면(`/`, `app/(wiki)/page.tsx`)의 전체 문서 목록은 그대로 `updated_at` 기준 `listDocuments`를 쓴다. 사이드바만 열람 기록으로 바뀌었다.

### 이미지 업로드·붙여넣기

- 편집기 툴바의 "이미지" 버튼(파일 선택, 다중 선택 가능)과 본문 `<textarea>`에 이미지 붙여넣기(`onPaste`)로 삽입한다. 이미지 MIME만 허용(`png`, `jpeg`, `gif`, `webp`), 25MB 제한은 DB 체크 제약과 API 양쪽에서 검증한다.
- 업로드: `POST /api/attachments` (multipart, `file`+`documentId`) — 서버에서 SHA-256을 계산해 `{userId}/{documentId}/{sha256}.{ext}` 경로로 비공개 Storage 버킷(`attachments`, 기존 인프라)에 저장하고 `attachments` 테이블에 기록한다. 같은 내용을 다시 올리면 경로가 같아 자동 중복 제거된다.
- 렌더링: 업로드 응답이 돌려주는 URL은 `/api/attachments/{id}` 하나뿐이다(서명 URL이 아님). 편집기 미리보기와 읽기 화면이 **완전히 같은 이 URL을 그대로** 쓰기 때문에 "조회에서도 동일하게 보이도록"이 자동으로 성립한다. `GET /api/attachments/[id]/route.ts`가 소유자 인증 후 Storage에서 바이트를 그대로 스트리밍하고 `Cache-Control: private, max-age=31536000, immutable`을 붙인다(경로가 내용 해시 기반이라 안전).
- **아직 저장 안 된 새 문서에서 이미지를 올리는 경우:** `attachments.document_id`가 NOT NULL이라 저장 전에는 붙일 대상이 없다. 그래서 **첫 이미지 업로드 시점에만** `status='draft'`인 숨김 문서를 지연 생성한다(`createDraftDocumentAction` → `features/documents/data.ts`의 `createDraftDocument`, 제목은 사용자가 입력한 값이 있으면 그것, 없으면 `제목 없음 <timestamp>`). 이 draft 문서는:
  - `listDocuments`(홈 "문서" 목록)에서 `status <> 'draft'` 필터로, `search_documents` SQL 함수에서도 같은 조건으로 제외된다. `recent_views`는 draft가 읽기 화면에 노출된 적이 없으므로 자연히 걸리지 않는다.
  - 사용자가 실제로 "저장"을 누르면(폼의 숨은 `draftDocumentId` 필드) **기존 `createDocumentAction`이 그대로 새 문서를 정상 생성**하고, 그 직후 `reparentAttachments`로 첨부의 `document_id`를 새 문서로 옮긴 뒤 `deleteDraftDocument`로 draft 행을 삭제한다. `update_document` SQL 함수나 슬러그 규칙은 전혀 건드리지 않았다 — 새 문서 생성 경로를 한 번 더 타는 것뿐이라 리스크가 작다.
  - **알려진 한계:** 사용자가 이미지만 올리고 문서를 끝내 저장하지 않으면 그 draft 문서와 첨부는 DB에 영구히 남는다(정리 워커가 아직 없음). 목록에는 절대 안 보이지만 디스크·행 낭비는 있다. 필요해지면 "N일 지난 draft 정리" 작업을 추가할 것.
- `markdown-renderer.tsx`는 수정하지 않았다 — 표준 Markdown 이미지 문법(`![alt](url)`)은 react-markdown이 기본으로 렌더링하며, `raw HTML 비활성화` 정책과 무관하다(HTML `<img>` 태그를 직접 쓴 경우만 막힌다).

### Markdown·텍스트 가져오기

- 경로: `/settings/import` (설정 화면에도 진입 링크 있음). **1차 버전 범위는 개별 `.md`/`.markdown`/`.txt` 파일 다중 선택만이다 — ZIP·Obsidian vault 가져오기는 아직 없다** (설계 문서에는 있지만 보안 검증 비용이 커서 의도적으로 다음 단계로 미뤘다, 사용자 확인됨). 확장자는 Notion 사례를 참고해 `.txt`까지 포함했다(Obsidian은 `.md`만 인정).
- **2단계 흐름**: `POST /api/imports`(분석 — 파일마다 제목·충돌·경고를 계산하고 원문을 `data-jobs` 버킷에 저장, `import_jobs`/`import_items`에 기록, 최대 10개 표본을 `MarkdownRenderer`로 미리보기) → 사용자가 충돌 정책(건너뛰기/이름 바꾸기) 선택 → `POST /api/imports/[jobId]/commit`(실제 문서 생성).
- YAML frontmatter는 `.md`/`.markdown`에서만 파싱한다(`gray-matter` 신규 의존성, `lib/markdown/frontmatter.ts`). `title` 키가 있으면 파일명 대신 그 값을 쓰고, `aliases`는 `document_aliases`로 옮긴다. `.txt`는 frontmatter를 시도하지 않는다.
- **문서 생성은 기존 `createDocument`(→ `create_document` RPC)를 파일마다 그대로 재사용한다.** 새 RPC를 만들지 않았다 — 이미 있는 중복 감지(`23505`)를 그대로 활용해 `skip`/`rename` 정책을 구현했다(`rename`은 `제목 (2)`, `제목 (3)`... 최대 20회 시도). 위키링크는 배치 안에서 먼저 저장된 문서만 해석된다 — 배치 안에서 뒤쪽 파일이 앞쪽 파일을 참조하는 정방향 참조는 재저장 전까지 안 풀린다(알려진 한계, 명시하지 않으면 링크 손실처럼 보일 수 있음).
- **회귀 발견 및 수정: Supabase Storage 키는 비-ASCII 문자를 거부한다.** 한글 파일명(`메모.txt`, `구름.md`)을 그대로 Storage 경로에 쓰면 `StorageApiError: Invalid key`로 실패했다. `features/imports/data.ts`의 `storageKeyFor()`가 상대경로를 `Buffer.from(path,'utf8').toString('base64url')`로 인코딩해 업로드/다운로드 키로 쓰고, `import_items.relative_path`(화면 표시용)는 원본 한글 그대로 둔다. **다른 기능에서 Storage에 사용자 파일명을 직접 쓸 일이 생기면 반드시 이 패턴을 참고할 것** — attachments 업로드는 애초에 SHA-256 해시를 키로 써서 이 문제를 겪지 않았다.
- **회귀 발견 및 수정: 가져온 문서의 제목이 본문에도 중복 표시되는 문제.** 원본 md 파일이 `# 제목` 형태로 시작하는 게 흔한데, 이 제목이 문서의 실제 `title`(페이지 상단에 큰 글씨로 별도 표시됨)과 겹치면 같은 텍스트가 화면에 두 번 나와 "인터페이스가 깨진 것"처럼 보였다. `features/imports/parse.ts`의 `stripLeadingTitleHeading()`이 본문 첫 줄이 제목과 일치하는 H1이면 제거한다(정규화 비교, 대소문자·공백 무시). **이미 가져온 기존 문서는 소급 수정되지 않는다** — 수동으로 첫 줄을 지우고 저장해야 한다.
- **편집기에서도 파일 1개를 바로 불러올 수 있다.** `/documents/new`와 편집 화면 툴바에 "파일 불러오기" 버튼이 추가됐다(`document-editor.tsx`). `/settings/import`의 다중 파일 마법사와 달리 여기는 1개 파일만 받고, 커서 위치에 본문을 삽입하며 제목이 비어있을 때만 파일에서 뽑은 제목을 채운다(기존 제목은 덮어쓰지 않음). 내부적으로 `parseImportFile`(가져오기와 동일 로직, 위 중복 제목 제거 포함)을 그대로 재사용한다.

### 정리(lint) 제안 — 설계 13절 A0

설계 13절(AI 지식 유지보수, BYOK)의 첫 단계로, **AI 호출 없이** SQL만으로 정리 제안을 만들고 사용자가 승인하는 화면이다. 이후 A1(BYOK Query·AI 요약)이 같은 `document_suggestions` 테이블과 승인 UI를 재사용한다.

- 경로: `/settings/lint` (설정 화면에 대기 건수와 함께 진입 카드). 페이지 진입과 설정 화면 진입 시 `refresh_lint_suggestions()`를 호출해 현재 상태로 다시 계산한다.
- **미해석 위키링크를 이제 저장한다.** 이전에는 `create_document`/`update_document`가 제목·별칭에 매칭되지 않는 `[[링크]]`를 그냥 버렸다. `202609150010_lint_suggestions.sql`이 링크 해석을 공용 `index_document_links()`로 빼고, 실패한 링크를 `document_unresolved_links`에 남긴다. 이 때문에 앱이 RPC에 넘기는 `p_link_targets` 항목에 원문 `title`이 추가됐다(`linkTargetsForStorage`). `jsonb_to_recordset`이 모르는 키를 무시하므로 옛 호출도 깨지지 않는다.
- **이 마이그레이션 이전에 저장된 문서는 미해석 링크가 비어 있다.** 재저장하거나 정리 화면의 "모든 문서 다시 색인"을 누르면 채워진다(`reindexAllDocuments` → 문서마다 `reindex_document_links` RPC, 리비전·version 변경 없음). SQL 백필은 앱의 `normalizeConcept`(NFKC·ko-KR 소문자)를 SQL에서 정확히 재현하기 어려워 의도적으로 하지 않았다.
- 제안 4종과 승인 동작:
  - `forward_link` — 저장 당시엔 없던 문서가 생겨 이제 해석되는 링크. 승인 → `reindex_document_links`. 백링크가 생긴다.
  - `fill_summary` — `summary = ''`인 활성 문서. 목록에서 `deriveSummary(body)` 결과를 미리 보여주고, 승인 → 기존 `updateDocument`로 summary만 바꿔 저장(리비전 생성, frontmatter 보존). 파생 결과가 비면 "직접 입력"(편집 화면 링크)만 제공한다.
  - `broken_link` — 지금도 해석되지 않는 링크. 자동 적용 없음. "새 문서 만들기" → `/documents/new?title=…`(제목 프리필, draftKey는 `new:<title>`이라 일반 새 문서 임시저장과 섞이지 않음).
  - `orphan` — 들어오고 나가는 링크가 모두 0인 활성 문서. 정보 표시와 무시만.
- `document_suggestions` 고유키 `(owner_id, kind, document_id, target_key)`. `refresh`는 현재 발견을 pending으로 upsert하고, 더 이상 해당 없는 행은 상태와 무관하게 삭제하며, `dismissed`는 발견이 유지되는 한 그대로 둔다. 즉 로그가 아니라 **큐**다 — `applied` 행도 다음 refresh에서 사라진다.
- `lint_findings()`는 발견 계산 전용 SQL 함수(`stable`)고 `refresh_lint_suggestions()`가 이걸 두 번 참조한다. 임시 테이블을 쓰지 않은 이유는 SQL 테스트가 한 트랜잭션에서 여러 번 호출하기 때문이다.
- `deriveSummary`(`lib/markdown/summary.ts`)는 설계 5절 "첫 유효 문단 300자 파생" 규칙의 첫 구현이다. frontmatter `summary`/`description` 우선 → 코드·제목·이미지·표·HTML 제외 첫 문단 → 인라인 마크업·위키링크·리스트/인용 마커 제거 → 300자 초과 시 말줄임. **아직 저장 경로에는 연결하지 않았다** — 새 문서를 요약 없이 저장해도 자동으로 채우지 않고 정리 제안으로만 나온다(설계상 "파생 요약은 저장 시 갱신"과 다름, 의도적 보류).
- 화면은 설계 8절의 인터페이스 텍스트 최소화 원칙에 따라 안내 문장 1개만 두고 `?` 가이드 컴포넌트는 만들지 않았다(아직 프로젝트에 `GuideTooltip`이 없다).

## 반드시 주의할 기술 사항

### 한글 슬러그

브라우저 URL은 한글 슬러그를 퍼센트 인코딩한다. Next.js 라우트의 `params.slug`도 이 인코딩값으로 들어오는 사례가 확인됐다.

- 읽기 화면: `app/(wiki)/documents/[slug]/page.tsx`
- 편집 화면: `app/(wiki)/documents/[slug]/edit/page.tsx`
- 안전 디코더: `lib/markdown/slug.ts`의 `decodeDocumentSlug`

새로운 `/documents/[slug]/...` 라우트를 추가할 때는 조회 전에 반드시 `decodeDocumentSlug`를 사용한다. 이 처리가 빠지면 한글 제목 문서가 404가 된다.

### 매직 링크 세션

`app/auth/callback/route.ts`는 Supabase의 세션 쿠키를 **리다이렉트 응답 객체 자체**에 설정한다. 쿠키가 붙은 응답과 리다이렉트 응답을 분리하면, 로그인 직후 첫 페이지에서 문서 목록 조회가 실패하고 새로고침 후에만 정상 진입하는 회귀가 생긴다.

### 로컬 Supabase 계정

- 개발 소유자 이메일: `owner@example.com` (`.env.local`의 `OWNER_EMAIL`)
- 개발 메일함: `http://localhost:54324` (Mailpit)
- `supabase db reset`은 로컬 Auth 사용자와 문서도 지운다.
- DB를 초기화했다면 `owner@example.com`을 Supabase Admin API로 다시 만들어야 한다. 로그인 정책은 신규 가입을 막고(`shouldCreateUser: false`), 기존 소유자만 매직 링크를 받을 수 있게 되어 있다.
- 비밀 키·`.env.local` 값은 커밋하거나 문서에 기록하지 않는다.

## 검증 현황

마지막 검증 시점에 다음을 통과했다.

- Vitest: 91개 테스트
- TypeScript 검사
- ESLint
- Next.js 프로덕션 빌드
- 브라우저에서 실제 로그인 후 `/settings`의 7개 항목을 각각 변경 → 즉시 반영 → 새로고침 후 DB 값 유지 확인
- 테마 변경이 전체 화면에 즉시 반영되는 것, 줄바꿈 모드 전환이 문서 읽기 화면에 반영되는 것, `tooltip_enabled` 끄면 호버 미리보기가 열리지 않는 것을 확인
- `search_documents` SQL 함수를 `psql`에서 `auth.uid()`를 직접 세팅해 단독 검증
- 브라우저에서 ⌘K 팔레트 열기·타이핑·디바운스 결과·화살표 키 탐색·Enter 선택·최근 검색어 삭제/전체삭제, `/search?q=` 페이지 직접 접근, 사이드바 "최근 문서" 실제 갱신과 제거(hidden) 동작을 확인
- **회귀 발견 및 수정:** 로컬에 `next start`로 띄운 오래된 프로세스가 포트 3000을 점유하고 있어 최신 코드가 반영되지 않은 채 테스트를 진행했던 적이 있었다. 브라우저 검증 전에는 `lsof -i :3000` 등으로 실제로 최신 `next dev`가 떠 있는지 확인할 것.
- 새 문서(미저장) 화면에서 이미지 업로드 → draft 문서 생성 확인(psql로 `status='draft'` 행 확인) → 실제 "저장" → 새 문서로 첨부가 재소속되고 draft 행이 삭제되는 것을 DB에서 직접 확인
- 기존(저장된) 문서 편집 화면에서 이미지 붙여넣기 → 편집기 미리보기와 저장 후 읽기 화면에 동일하게 렌더링되는 것을 DOM에서 `naturalWidth` 확인까지 포함해 검증
- 이미지가 아닌 파일(`text/plain`) 업로드 시 400 거부 확인
- **회귀 발견 및 수정:** 첫 구현에서 업로드 응답 URL을 `/api/attachments/{id}`로 만들어놓고 GET 핸들러는 `/api/attachments?id=`만 받도록 짜서 모든 이미지가 404였다. `app/api/attachments/[id]/route.ts`로 분리해 해결 — 이런 API 경로 불일치는 타입체크로 못 잡으므로 반드시 브라우저에서 실제 이미지가 뜨는지 확인해야 한다.
- 브라우저에서 사이드바 접기/펼치기 토글, 새로고침 후 상태 유지, 모바일 폭에서 토글 버튼 자체가 숨는 것을 확인
- 브라우저에서 이미지 클릭 → 라이트박스 오픈 → Esc로 닫힘까지 확인
- 브라우저에서 `.md`(YAML frontmatter+aliases+위키링크)·`.txt`·제목 중복 파일 3개를 실제로 분석→미리보기→가져오기 실행까지 전 과정 확인. `civ6` alias가 실제로 생성됐는지 DB에서 직접 확인, `구름` 중복이 `rename` 정책으로 `구름 (2)`가 된 것을 확인
- **회귀 발견 및 수정:** 한글 파일명을 그대로 Storage 키로 써서 한글 파일이 전부 "실패"로 뜨는 버그를 발견 → `storageKeyFor()`(base64url 인코딩)로 수정. 영문 파일명만으로 테스트했다면 못 잡았을 버그라 유니코드 파일명으로 반드시 확인해야 한다.
- **사용자가 실제로 가져오기를 써보고 발견한 버그 2건을 수정:** (1) 본문 첫 줄에 제목과 같은 `# 제목`이 있으면 페이지 제목과 중복 표시되던 문제, (2) 편집기에서는 이미지만 올릴 수 있고 텍스트/md 파일은 `/settings/import`에서만 가능했던 문제(1개 파일 한정 "파일 불러오기" 버튼을 편집기에도 추가). 브라우저에서 실제 md 파일을 편집기에 불러와 제목 자동 채움·중복 헤딩 제거·기존 제목 보존(덮어쓰지 않음)을 모두 확인. 이미 잘못 가져와진 기존 문서 1건은 사용자 화면에서 직접 첫 줄을 지우고 재저장해 정리함(소급 수정 기능은 없음).
- `Blob.prototype.text`가 jsdom에 없어서 파일 읽기 테스트가 실패하던 문제 → `tests/setup.ts`에 `FileReader` 기반 폴리필 추가(프로덕션 코드는 표준 API 그대로 사용, 테스트 환경만 보정).
- 정리 제안: `supabase/tests/lint_suggestions.sql`로 저장→깨진 링크→대상 생성→정방향 전환→기각 유지→재색인(리비전 없음)→요약 채움→타 사용자 격리를 검증. 브라우저에서 "요약 저장"(문명 6) → 재저장으로 `[[과학 승리]]` 깨진 링크 감지 → "새 문서 만들기" 제목 프리필 → 저장 → "이제 연결할 수 있는 링크"로 전환 → "링크 연결" → 과학 승리 문서에 문명 6 백링크 표시까지 확인. "무시" 새로고침 유지, 모바일 폭 가로 스크롤 없음, "모든 문서 다시 색인"으로 기존 문서의 깨진 링크 6건이 새로 드러나는 것 확인. **이 과정에서 로컬 DB에 "과학 승리" 문서를 실제로 만들었다.**
- **주의:** `supabase/tests/rls.sql`은 픽스처 이메일 `owner@example.com`이 로컬 개발 계정과 겹쳐 현재 로컬 DB에서는 실패한다(이번 변경과 무관, `db reset` 직후에만 통과).
- `midnight` 테마: 브라우저에서 스와치 클릭 → 즉시 적용 → 다크 모드 전환까지 확인. `getComputedStyle`로 `--color-bg`/`--color-accent`/`--radius-md`/`--space-6` 값이 실제로 반영됐는지 직접 대조. 이 세션에서 로컬 계정의 활성 테마를 `midnight`+다크로 남겨뒀다(사용자가 마음에 들어해서 되돌리지 않음).

## 다음 개발 우선순위

1. **주석:** 문서 범위 앵커부터 시작하고, 블록 단위 모델로 확장하지 않는다.

설정 화면·검색/최근 기록·이미지 업로드·Markdown 가져오기(개별 파일)는 구현 완료. 남은 선택 과제:
- 설정: 새 기기 간 깜빡임 방지용 쿠키 캐시(현재는 로컬 저장소만).
- 검색: 본문 부분 일치(design doc 랭킹 5순위) — trigram 인덱스가 없는 `body_markdown`에 대한 검색이라 성능 검증이 필요하다.
- 이미지: 저장 안 된 draft 문서 자동 정리(N일 경과 시 삭제) 워커가 없다. 지금은 방치돼도 목록엔 안 보이지만 무한히 쌓인다.
- 이미지: 첨부파일 삭제 UI가 없다(본문에서 이미지 마크다운을 지워도 Storage 객체·DB 행은 남는다). 디자인 문서의 "일일 정리 Worker"가 도입되면 자연히 해결될 여지가 있다.
- **가져오기: ZIP·Obsidian vault 지원이 아직 없다.** (사용자 확인 후 1차 범위에서 의도적으로 제외) 나중에 하게 되면 경로 이탈·심볼릭 링크·압축 폭탄 검증과, 같은 ZIP 안 상대경로 이미지를 `attachments` 업로드 흐름으로 옮기는 절차가 필요하다.
- 가져오기: 배치 내 정방향 위키링크 참조(뒤 파일이 앞 파일을 가리키는 경우, 그 반대는 됨)가 안 풀린다. 재저장하면 해결되지만 자동화되어 있지 않다.
- 가져오기·저장: 요약 없이 저장된 문서는 정리 화면의 `fill_summary` 제안으로만 채워진다. `deriveSummary`를 저장·가져오기 경로에 직접 연결해 자동으로 채울지는 결정 필요(설계 5절은 자동 파생을 말하지만, 사용자가 비워 둔 것과 구분이 안 되는 문제가 있다).
- 정리: 설계 13절 A1(BYOK 설정, `ai_runs`, 카드 내 Query·문서로 저장, AI 요약 채우기)이 다음 단계다. `document_suggestions.kind` enum에 AI용 값과 `run_id` 컬럼을 추가하는 마이그레이션이 필요하다.
- `midnight` 테마의 라이트 모드 색상은 참고 사이트에 없어 새로 추측해 만든 값이다(다크 모드만 실측 대조함). 사용자가 라이트 모드로 실제로 써보고 마음에 안 들면 조정 필요.

그래프, 협업, 공개 공유, 플러그인은 Core Alpha가 통과되기 전 시작하지 않는다. AI는 설계 13절 A0·A1만 예외로 병행한다.
