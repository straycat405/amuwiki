# 아무위키 개발 인수인계

최종 갱신: 2026-09-14 (설정 화면 반영)

## 작업 원칙

- 사용자와의 모든 대화는 한국어로 한다.
- 기능 단위마다 `npm run test`, `npm run typecheck`, `npm run lint`, `npm run build`를 실행한다.
- DB 변경은 마이그레이션으로만 추가한다. 기존 사용자의 로컬 문서를 지우는 `supabase db reset`은 명시적인 필요·승인 없이는 실행하지 않는다.
- 기능 또는 버그 수정이 끝나면 반드시 커밋하고 `origin/main`에 푸시한다.
- 사용자 데이터, 계정, 외부 서비스 설정처럼 되돌리기 어렵거나 제품 정책을 바꾸는 작업은 구현 전에 확인한다.

## 구현 완료 항목

### 기반·인증·문서

- 소유자 1인 이메일 매직 링크 로그인. DB와 RLS는 다중 사용자 격리 구조다.
- 문서 생성·조회·수정, 명시적 서버 저장, localStorage 임시 자동 저장, 리비전·낙관적 버전 충돌 처리.
- 휴지통 소프트 삭제·복원.
- Markdown 렌더링(GFM, raw HTML 비활성화)과 Wiki link 문법:
  - `[[문서 제목]]`
  - `[[문서 제목|표시명]]`
  - `[[문서#제목]]`
- 제목 변경 시 이전 제목을 별칭으로 보존하고, 제목·별칭 충돌은 저장을 거부한다.
- 저장 시 명시 링크를 `document_links`에 색인하고, 읽기 화면에 역링크와 언급 횟수를 표시한다.

### 탐색 경험

- Wiki link 호버 미리보기(기본 지연 450ms, 설정 화면에서 250~800ms 및 켬/끔 조절 가능).
- 링크 클릭 시 고정 카드, 카드 내 중첩 링크, 카드 드래그 이동, 최대 3개 고정 카드.
- 미리보기 API는 인증된 소유자만 사용한다: `GET /api/documents/preview?slug=...`.

### 줄바꿈

- 기본 렌더 정책은 `hard`: 편집기의 Enter 한 번이 읽기·미리보기 화면에서 `<br>`로 표시된다.
- 인라인 코드·코드 블록은 영향을 받지 않는다.
- `user_preferences.line_break_mode`(`hard | soft`)는 설정 화면에서 변경할 수 있고, `MarkdownRenderer`가 즉시 반영한다.

### 설정 화면

- 경로: `/settings`. `user_preferences`의 7개 컬럼(`theme_key`, `color_mode`, `font_preset`, `font_scale`, `content_width`, `tooltip_enabled`, `tooltip_delay_ms`, `line_break_mode`)을 전부 노출한다. `tooltip_lock_mode`는 DB 체크 제약상 `click` 한 값만 허용되어 설정 항목에서 제외했다.
- **DB가 최종 원본이다.** 컨트롤을 조작하면 `PreferencesProvider`가 화면에 즉시 반영(낙관적 업데이트)한 뒤 `updatePreferencesAction`으로 저장하고, 실패하면 이전 값으로 되돌리며 오류 메시지를 보여준다.
- `localStorage`(`amuwiki:appearance`)는 테마·명암·글꼴·글자크기·본문폭만 캐시해 `app/layout.tsx`의 `beforeInteractive` 스크립트가 첫 페인트 전에 적용한다. **쿠키 캐시는 아직 구현하지 않았다** — 제품 설계 문서(279행)는 로컬 저장소와 쿠키 모두를 언급하지만 현재는 로컬 저장소만 있다.
- 글자 크기(`--font-scale`)와 본문 폭(`--content-width`) 값은 `styles/tokens.css`의 `data-scale`/`data-width` 속성으로 제어한다.
- 호버 미리보기 지연·활성화는 `components/document/wiki-link-explorer.tsx`가 `usePreferences()`로 읽는다. `tooltip_enabled`가 꺼지면 호버 시작 자체를 막고, 클릭으로 카드를 고정하는 동작에는 영향을 주지 않는다.

## 반드시 주의할 기술 사항

### 한글 슬러그

브라우저 URL은 한글 슬러그를 퍼센트 인코딩한다. Next.js 라우트의 `params.slug`도 이 인코딩값으로 들어오는 사례가 확인됐다.

- 읽기 화면: `app/(wiki)/documents/[slug]/page.tsx`
- 편집 화면: `app/(wiki)/documents/[slug]/edit/page.tsx`
- 안전 디코더: `lib/markdown/slug.ts`의 `decodeDocumentSlug`

새로운 `/documents/[slug]/...` 라우트를 추가할 때는 조회 전에 반드시 `decodeDocumentSlug`를 사용한다. 이 처리가 빠지면 한글 제목 문서가 404가 된다.

### 매직 링크 세션

`app/auth/callback/route.ts`는 Supabase의 세션 쿠키를 **리다이렉트 응답 객체 자체**에 설정한다. 쿠키가 붙은 응답과 리다이렉트 응답을 분리하면, 로그인 직후 첫 페이지에서 문서 목록 조회가 실패하고 새로고침 후에만 정상 진입하는 회귀가 생긴다.

### 로컬 Supabase 계정

- 개발 소유자 이메일: `owner@example.com` (`.env.local`의 `OWNER_EMAIL`)
- 개발 메일함: `http://localhost:54324` (Mailpit)
- `supabase db reset`은 로컬 Auth 사용자와 문서도 지운다.
- DB를 초기화했다면 `owner@example.com`을 Supabase Admin API로 다시 만들어야 한다. 로그인 정책은 신규 가입을 막고(`shouldCreateUser: false`), 기존 소유자만 매직 링크를 받을 수 있게 되어 있다.
- 비밀 키·`.env.local` 값은 커밋하거나 문서에 기록하지 않는다.

## 다음 개발 우선순위

1. **검색·최근 기록:** 상단 검색, 한글 부분 검색, 최근 문서·최근 검색어 기록/편집.
2. **이미지 업로드·클립보드 붙여넣기:** 편집기에서 이미지 업로드 버튼과 클립보드 붙여넣기로 이미지를 삽입하고, 읽기 화면에서도 편집기와 동일하게 보이게 한다. (2026-09-14 수동 테스트 중 발견한 요구사항)
   - `attachments` 테이블과 비공개 Storage 버킷(`attachments`, 25MB 제한)·RLS 정책은 `supabase/migrations/202609140001_initial_schema.sql`, `202609140002_private_storage.sql`에 이미 구현되어 있다. 남은 것은 애플리케이션 계층뿐이다.
   - 필요한 것: 업로드 API(서명 업로드 URL 발급, MIME·크기 검증 — 제품 설계 문서 588행 `POST /api/v1/attachments` 참고), 편집기의 업로드 버튼·붙여넣기 핸들러, 삽입된 Markdown 이미지 문법(`![대체텍스트](경로)`), 읽기 화면에서 비공개 버킷 객체를 보여줄 서명 URL 발급(또는 프록시 라우트).
   - Markdown 가져오기(3번)가 첨부파일 복사 로직에 의존하므로 이 작업을 먼저 끝내는 것이 유리하다.
3. **Markdown 가져오기:** 다중 파일/ZIP은 반드시 분석 → 표본 확인 → 확정 흐름으로 구현하고, 기존 문서에 즉시 쓰지 않는다.
4. **주석:** 문서 범위 앵커부터 시작하고, 블록 단위 모델로 확장하지 않는다.

설정 화면(테마·명암·글꼴·글자크기·본문폭·줄바꿈·호버 미리보기)은 구현 완료. 남은 선택 과제: 새 기기 간 깜빡임 방지용 쿠키 캐시(현재는 로컬 저장소만).

그래프, 협업, 공개 공유, 플러그인, AI 기능은 Core Alpha가 통과되기 전 시작하지 않는다.
