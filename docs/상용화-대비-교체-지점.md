# 상용화 대비 — 교체 지점과 미착수 항목

> 소유자 1인 MVP에서 내린 결정 중, 가입 개방·상용화 시 바꿔야 하거나 새로 필요한 것을 모아둔다. 각 항목은 "지금 결정 → 그때 교체 → 교체 비용을 낮추기 위해 지금 지키는 경계" 순서로 적는다. 설계 원본은 [아무위키-제품-기술-설계.md](./아무위키-제품-기술-설계.md).

## AI (설계 13절)

| 항목 | MVP 결정 | 상용화 시 | 지금 지키는 경계 |
|---|---|---|---|
| API 키 보관 | 앱 레벨 AES-256-GCM, 서버 env `AI_KEY_ENCRYPTION_SECRET` 하나 | KMS 봉투 암호화 또는 Vault + 서비스 롤. env 비밀 하나가 전 사용자 키의 단일 실패점이라 유출 시 전부 재암호화·재등록 | `lib/ai/crypto.ts`의 `encryptApiKey`/`decryptApiKey` 두 함수만 저장 형식을 안다. 암호문에 버전 접두어를 두어 재암호화 마이그레이션이 가능하게 한다 |
| Query 컨텍스트 | 카드 문서 전문 + 직접 링크(나가는 링크·백링크) 최대 5개 요약 | 설계 5절 관련 문서 랭킹(공통 개념 수)으로 교체, 문서 규모에 따라 토큰 상한 정책 | 컨텍스트 조립을 `features/ai/context.ts` 함수 하나로 분리한다 |
| Query 답변 저장 | `status='draft'` 문서 생성 후 편집 화면 이동 | 동일하되 미저장 draft 정리 워커 필수 | 이미지 업로드 draft와 같은 정리 대상. 워커 도입 시 두 경로가 함께 해결된다 |
| AI 요약 채우기 | 파생 불가 문서만, 순차 호출 | Message Batches API + 작업 큐 테이블(설계 3절) | 결과는 `document_suggestions(kind='ai_summary')`로 저장하므로 실행 방식만 바꾸면 된다 |
| 모델 선택 | `AI_MODEL` env 고정 | 허용 목록(`AI_ALLOWED_MODELS`) + 사용자 선택 | 모델 문자열을 `lib/ai/client.ts`에서만 읽는다 |
| 비용 청구 | BYOK만 | "구독 + 플랫폼 키" 옵션 추가 가능 | `ai_runs.billing_source`(`byok` / `platform`)를 처음부터 둔다 |

## AI — MVP에서 아예 하지 않는 것

- **속도 제한·남용 방지**: 사용자당 분당 호출 수, 프롬프트 길이 상한, 동시 요청 제한. Route Handler 앞에 미들웨어 자리를 비워둔다.
- **스트리밍과 배포 환경**: 설계 3절의 Edge/서버리스 배포는 실행 시간 상한이 있다. 긴 답변 스트리밍은 Node 런타임을 요구할 수 있으며, 배포 대상 결정(설계 20절 미결) 때 다시 판단한다.
- **데이터 처리 고지**: 사용자 문서가 외부 API로 전송된다는 약관·개인정보 고지.
- **감사 로그**: 키 등록·삭제·캡 변경 이벤트 기록. `ai_runs`와 별개.

## AI 외 — 이미 알려진 다중 사용자 전환 항목

- 가입·온보딩·계정 복구·탈퇴(설계 18절).
- 미저장 draft 문서·참조 잃은 첨부 정리 워커(인수인계 "다음 개발 우선순위").
- `rls.sql` 테스트 픽스처가 로컬 개발 계정과 충돌하는 문제 — CI에서는 빈 DB로 돌리므로 무관하나, 픽스처 이메일을 예약 도메인으로 바꾸는 편이 안전하다.
- 검색 계층 교체(pg_trgm → 외부 검색 엔진, 설계 11절).
- 관련 문서 랭킹 캐시(설계 5절).
